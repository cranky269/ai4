# 整体联调任务定义（T1–T5）

> 每个任务 = 一个飞行场景 + 量化判据，独立判「过 / 不过」。判据数值取《拆解文档》第七章基线，整定须记录。

## 前置（各任务共用）

- **一键 launch**：Gazebo world + 靶机脚本 + 全节点栈，场景可重复。
- **可视化**：RViz 看航迹 / 航点，rqt 看误差与 setpoint。
- **位姿**：起飞前确认 `/mavros/local_position/pose` 有数据。navigator 无位姿即静默不发布 → `/ctrl/radar` 无流、mux 无转发，只靠 PX4 failsafe。
- **钩子**：`rostopic pub /state` 强制通道。转发由 `/control_mux` 完成，`/state_machine` 只管放行哪一路；mux 未收到 `/state` 时默认放行 `/ctrl/radar`。强制时 `/state` 须单点发布（不启状态机），正向任务由状态机自然发布。

## T1 雷达链起飞引导闭环

- **验收**：阶段 2 + 3
- **链路**：`radar_sim → /cluster → /tracker → /navigator → /control_mux → PX4`（`RADAR_GUIDE`）
- **顺序**：位姿有数据 → navigator 出 `/ctrl/radar` 流 → 再切 OFFBOARD（PX4 要求先有流）
- **状态机**：非必需（mux 默认雷达路）；若启动须确认其不离开 `RADAR_GUIDE`（靶机不入画或未启 `/detector`）

判据：

1. 稳定 OFFBOARD，setpoint 50Hz 无断流；
2. 航迹误差 < 1 m（对 `/target/pose` 真值）；
3. 断续点迹连成平滑航迹（协方差收敛）；
4. 距上次**非空** `/radar/tracks` 超过 `hold_timeout` 秒 → 自判悬停，不掉线（按秒计，与状态机 K 帧无关；K 帧归 T4）。

**重点观察**：`z_thresh`、`eps / min_samples` 整定；Kalman 时序；近邻关联交叉错配留记录。

## T2 视觉链伺服验证

- **验收**：阶段 4 前置
- **链路**：`camera_node → /detector → /visual_tracker → /pid_controller → /control_mux`
- **场景**：靶机入画；钩子固定 `VISUAL_LOCK`（不启状态机）

判据：

1. 符号正确：偏右 → 右偏航；偏下 → 俯冲；面积小（远）→ 前进；
2. 抖动 < 20 px；超调 < 15%；
3. 深度按直接面积误差：面积 < 期望(0.10) → 正向且受 `max_out` / `forward_limit(2.0)` 双限幅；≈ 期望 → 近零；≥ 阈值(0.35) → 末端速度 0.0；冷启动不饱和爆冲。

**重点观察**：`FRAME_BODY_OFFSET_NED` 下 yaw_rate / body velocity 符号；空 `Detections` / `VisualTrackArray` 照发。

## T3 兜底与故障行为（安全关键）

- **验收**：阶段 3 failsafe + 第八章第 7/8/9 条
- **分组**：**T3-R** 雷达通道（基准同 T1）、**T3-V** 视觉通道。兜底指令须走完 mux 才到飞控，注入须在对应通道下做。
- **做法**：逐点注入，注入 / 记录 / 恢复各一轮；测试期可放大 `~hold_timeout`（默认 0.2s 仅约 10 拍）。

### T3-R

| 注入 | 预期 |
|---|---|
| kill `/cluster` | 短时重发上一条 → 超时悬停，不掉 |
| `/radar/tracks` 持续空 | 空不刷新 `valid_age`，最终悬停，不得无限保持旧航点 |
| kill navigator 与 pid | 流断 > 0.5s → PX4 failsafe 切出 |

### T3-V

- **V1 钩子强制**（不启状态机）：只看 pid 侧；
- **V2 自然锁定**（状态机在跑）：pid 侧 + `/state` 冻结。

| 注入 | 预期 |
|---|---|
| kill `/detector` | pid 有界保持 → 零速，不掉；V2 下 `/state` 冻结属预期（非故障） |
| `/visual/tracks` 持续空 | 同上，收敛零速，不得无限重发旧速度 |
| 目标飞出画面 | pid 收敛零速；M 帧回退属 T4 |
| kill navigator 与 pid | 流断 > 0.5s → PX4 failsafe 切出 |

判据：

1. 短时重发上一条；长时悬停 / 零速，全程不掉（failsafe 除外）。验收口径按通道区分：**T3-R** 验「位置保持」（悬停为绝对量，应停在原位）；**T3-V** 只验「不坠、姿态可控」，位置漂移不作要求（零速为相对量，不构成定点保持，见设计原则第 3 条）；
2. 数据恢复后自动恢复跟踪，无需人工重发；
3. 两条路径分开验：上游断流但决策节点活 → 默认指令；决策节点也死 → 转发断路 → failsafe；
4. 保持窗口与 `hold_timeout` 一致，时钟层可复现。

## T4 状态机切换 + 仲裁

- **验收**：阶段 4 + 第四章规则 + 切换延迟 < 100 ms
- **场景**：靶机由远及近，面积自然越过 2%；钩子构造退出 / 熔断
- **顺序**：先雷达链、后 `/detector`，`/state` 稳定在 `RADAR_GUIDE` 后开始计数（否则开局 K 帧误进 `SEARCH/RTH`）

判据：

1. 切换延迟 < 100 ms（条件满足 → mux 放行视觉）；
2. N/M/K 符合转移表（自稳定首帧起算）：N 帧进 `VISUAL_LOCK`；M 帧丢目标回 `RADAR_GUIDE`；K 帧无航迹进 `SEARCH/RTH`；雷达恢复退出；
3. 优先级：锁定与丢失并存 → `VISUAL_LOCK`；`SEARCH/RTH` 仅由雷达恢复退出；
4. 节拍唯一为 `/detections`（另两路只刷缓存），某路慢不误判为空；
5. `/state` 按变化发布，mux 跟随；其他值回退 `/ctrl/radar`；
6. 记录切换瞬间指令突变幅度（供第九章优化 2 判定硬切）。

## T5 全流程拦截（中期验收）

- **验收**：阶段 5「雷达 → 视觉无卡顿」
- **剖面**：起飞 → OFFBOARD → `RADAR_GUIDE` → N 帧 → `VISUAL_LOCK` → 末端逼近 → 达阈值转末端速度（0.0，贴身跟随）→ 丢目标 M 帧 → 回 `RADAR_GUIDE` → 降落

判据：

1. 无卡死、无通道错配（mux 只放一路，日志可定位）；
2. 雷达 → 视觉切换平滑（结合 T4 突变幅度）；
3. 末端达阈值转末端速度，不持续加速；
4. 丢失按 M 帧回退，重搜兜底符合 T3；
5. 全程录包，可复盘切换时点与指令内容。

## 依赖顺序

```
T1 ──→ T2 ──→ T3 ──→ T4 ──→ T5
```

- T1 不过不进 T2；
- T3 先于 T4（兜底是切换联调的安全前提）；
- T5 需 T1–T4 全过，不带病进入。

## 可能的问题与优化（联调中再处理）

1. T2 抖动 / 超调需假 `/visual/tracks` 注入源（阶跃 bbox）才可量化；
2. 100 ms 延迟需先定义起止时间戳，录包离线量；
3. `covariance` 为 36 维展平，RViz 画不出，需 `MarkerArray` 或看对角线数值；
4. `hold_timeout` 默认 0.2s，保持档观察窗过短；
5. `/detections` 与 `/visual/tracks` 差一帧配对，面积过阈值晚一帧生效。
