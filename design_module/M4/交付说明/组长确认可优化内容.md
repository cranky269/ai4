## 优化项 1：给消息加 `Header`（时间戳）

**涉及消息**：`Detections.msg`、`VisualTrackArray.msg`

**现状**：按《数据类型.md》1.2 / 1.4 照搬定义，两个消息都**没有 `Header`**：

```
# Detections.msg
DetectedTarget[]  targets

# VisualTrackArray.msg
VisualTrack[]  tracks
```

**优化点**：加上 `std_msgs/Header`（`stamp` + `frame_id`）后可以：

- 直接量化**端到端延迟**（验收基线里有「切换延迟 < 100 ms」）；
- 做**时间戳对齐**（图像帧 ↔ 检测 ↔ 航迹）；
- 多机 / 录制回放时便于定位。

**为什么不加**：需要**改消息定义**，属接口变更，且当前不影响功能 ——
`/state_machine` 的 N/M/K 帧计数只用「消息到达」作节拍，**没有时间戳也能工作**。

**组长判定（2026-10-06）**：

> **不允许加，这个属于优化内容，目前不用管。**

**M4 侧现状**（已按判定处理）：

- 两个消息**一字未改**（保持《数据类型.md》照搬定义）；
- 延迟测量改用**节点日志打点**（`rospy.loginfo` 带 `rospy.Time.now()`），
  不依赖消息字段；
- 待将来验收确实需要量化延迟时，再按此条提议走接口变更流程。

## 优化项 2：BoT-SORT 的 GMC（全局运动补偿）

**来源**：《无人机项目实施拆解文档》**第九章第 3 条**，原文即写：

> GMC 列为**可选优化项**；若不上 BoT-SORT，纯 SORT 即可。

**优化点**：GMC 用原始图像估计背景运动，在**相机抖动大**（机载云台/机体振动）时
能让跟踪更稳。

**当前状态：不启用（默认关闭）**

| 项 | 说明 |
|---|---|
| 前置条件 | GMC 需要原始图像 |
| **前置条件已满足** | `track(detections, image)` 已按组长确认**新增图像入参**，节点订阅 `/camera/image_raw` |
| 未启用的原因 | 属「可选优化」，本期不做 |
| 已留接口 | `BotSortTracker.set_gmc(fn)` —— 注册钩子即可接入，**不需要重构** |
| 启用代价 | 每帧做一次全局运动估计（CPU 开销上升，虚拟机内无 CUDA） |

**建议**：等基础链路在仿真里跑通、并实测帧率有余量后再开。
