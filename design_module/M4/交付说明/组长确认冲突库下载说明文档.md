# 组长确认冲突库下载说明文档

> 记录人：M4 负责人　　组长确认时间：2026-10-06
> 适用模块：**模块 4 `/detector`**（唯一需要该依赖的节点）

---

## 1. 为什么有冲突

| 项 | 情况 |
|---|---|
| 项目基线（`requirements.txt` 顶部） | `numpy 1.17.4`（系统自带，**不升级**，避免影响其他组件） |
| `ultralytics`（YOLOv8/v11）要求 | `numpy >= 1.18.5` |
| **结论** | **直接安装会升级系统 numpy，破坏基线 → 冲突** |

另外：节点**必须用系统 `python3.8`** 运行（`venv` / `conda` 下 `import rospy`
会直接失败），所以也**不能用虚拟环境简单隔离**。

---

## 2. 组长确认的结论

> **允许安装**，但：
> 1. 安装目录放在**本工程下的 `lib/m4_deps`**（不放在各人 `HOME`，随仓库分发）；
> 2. **必须做好严格隔离**，避免其他文件 import 到这个 numpy。

落到具体路径：

```
<工程根>/catkin_ws/src/uav_tracking/lib/m4_deps/
```

## 3. 安装命令（**已实测可用的版本**）

> ⚠️ 下面这版是**在虚拟机里真跑通后修正过的**。若只写一条
> `pip3 install --target=... numpy==1.21.6 torch==2.4.1 ultralytics`，
> **实测会失败或装错**（3 个坑见 §3.1），请照抄本节的 6 步。

```bash
# ① 进工程根
cd /home/demo/桌面/ai4
DIR="$PWD/catkin_ws/src/uav_tracking/lib/m4_deps"

# ② torch / torchvision —— 必须走 pytorch 官方 CPU 索引（否则下 CUDA 版约 800MB）
pip3 install --target="$DIR" --index-url https://download.pytorch.org/whl/cpu \
    --no-cache-dir "torch==2.4.1+cpu" "torchvision==0.19.1+cpu"

# ③ ultralytics 本体（--no-deps：否则会拖走并覆盖上面的 CPU 版 torch）
pip3 install --target="$DIR" --index-url https://mirrors.aliyun.com/pypi/simple/ \
    --no-cache-dir --no-deps ultralytics

# ④ ultralytics 的运行时依赖（显式列出，不含 torch/torchvision/numpy/opencv）
pip3 install --target="$DIR" --index-url https://mirrors.aliyun.com/pypi/simple/ \
    --no-cache-dir \
    "matplotlib>=3.3.0" "pillow>=7.1.2" "pyyaml>=5.3.1" "requests>=2.23.0" \
    "psutil>=5.8.0" "polars>=0.20.0" "nvidia-ml-py>=12.0.0"
pip3 install --target="$DIR" --index-url https://mirrors.aliyun.com/pypi/simple/ \
    --no-cache-dir --no-deps "ultralytics-thop>=2.2.2"

# ⑤ numpy 放最后单独装（--no-deps 强降到批准的 1.21.6）
pip3 install --target="$DIR" --index-url https://mirrors.aliyun.com/pypi/simple/ \
    --no-cache-dir --no-deps --upgrade "numpy==1.21.6"

# ⑥ 必须剔除 opencv（否则遮蔽系统 cv2，与 cv_bridge 版本错配）
rm -rf "$DIR"/cv2 "$DIR"/cv2-* "$DIR"/opencv_python* "$DIR"/opencv_python.libs
```

装完体积约 **1.1 GB**，全部落在 `lib/m4_deps/`。

> **注意**：**不要**用 `pip3 install -r requirements.txt` 安装这几个包 ——
> `requirements.txt` 里这三行是**注释态**的，就是为了防止误升级系统 numpy。

### 3.1 为什么不能"一条命令搞定"（4 个实测坑）

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| 1 | **清华 PyPI 镜像 403** | `ERROR: Could not find a version that satisfies the requirement numpy==1.21.6 (from versions: none)` —— 连 `Collecting` 都没有、5 秒即失败，极易误判成"这个版本不存在" | 改用**阿里云** `mirrors.aliyun.com/pypi/simple/`（实测 200） |
| 2 | **torch 默认是 CUDA 版** | `pip install torch==2.4.1` 拉 `+cu121` 约 780 MB，再连带 `nvidia-*` 共 **2 GB+** 无用数据 | `torch==2.4.1+cpu` + pytorch 官方 CPU 索引（CPU 版仅 195 MB） |
| 3 | **`pip --target` 不把目标目录当"已安装"** | 装 ultralytics 时 pip 会**重新解析并覆盖** torch/torchvision 为 CUDA 版；numpy 也会被拉回 1.24.4。更隐蔽的是 `Target directory ... already exists. Specify --upgrade to force replacement` —— 它**静默不覆盖**，最后打出 `Successfully installed numpy-1.21.6` 但版本其实还是 1.24.4 | 依赖全部 `--no-deps` 分步显式装；numpy 放**最后**并加 `--upgrade`（必要时先 `rm -rf $DIR/numpy*`） |
| 4 | **`opencv-python` 遮蔽系统 `cv2`** | `detector_node` 同时用 `cv_bridge`（按系统 OpenCV 4.2.0 编译）和 `cv2`；新 cv2 会造成版本错配 | 装完删掉 `$DIR/{cv2,opencv_python*}`，让 `cv2` 回落系统 4.2.0 |
| 5 | **网络会 `ECONNRESET`，且 `pip ... \| tail` 会吞掉失败** | 装到一半断网，脚本仍打印"已装"（`\|` 后面取到的是 `tail` 的退出码，恒 0）——**失败被静默吞掉** | **直接用工程根的 `install_m4_deps.sh`**：已含 pip 重试（`--retries 5 --timeout 60` + shell 层重试 3 次）、**真实退出码判定**、**逐包 import 验证**、保留 pip 缓存（重跑不重下） |

### 版本选择理由

| 包 | 版本 | 理由 |
|---|---|---|
| `numpy` | **1.21.6** | `numpy 1.24` 才移除 `np.float` / `np.int` 等老别名，`1.21.6` 仍保留（仅告警），是对 ROS Noetic 最安全的**最小升级档**；且与 `scipy 1.8.1`（要求 `<1.25`）、`scikit-learn 1.3.2` 兼容 |
| `torch` | **2.4.1** | Python 3.8 的最后支持档（torch 2.5+ 要求 Python ≥3.9） |
| `torchvision` | **0.19.1** | 与 torch 2.4.1 配套 |
| 设备 | **CPU 版** | 虚拟机内无 CUDA，装 GPU 版纯属下 2.5 GB 无用数据 |

## 4. 严格隔离是怎么做到的

**只有 `scripts/detector_node.py` 一个文件**把该目录注入 `sys.path`，
且注入发生在 `import numpy / torch` **之前**：

```python
# catkin_ws/src/uav_tracking/scripts/detector_node.py
_LIB_DIR = os.path.abspath(
    os.path.join(os.path.dirname(os.path.abspath(__file__)), "..", "lib"))
if _LIB_DIR not in sys.path:
    sys.path.insert(0, _LIB_DIR)

_M4_DEPS = os.path.join(_LIB_DIR, "m4_deps")          # ← 只有本节点加它
if os.path.isdir(_M4_DEPS) and _M4_DEPS not in sys.path:
    sys.path.insert(0, _M4_DEPS)
```

**为什么其他节点拿不到它**：

| 机制 | 说明 |
|---|---|
| 其他节点壳只注入 `lib/` | 不注入 `lib/m4_deps` |
| Python 的查找规则 | `import numpy` 时只看 `sys.path` 各项**直接**下的 `numpy/`，即 `lib/numpy`（不存在），**不会**进 `lib/m4_deps/numpy` |
| 不写 `PYTHONPATH` / `.pth` | 不污染全局或用户环境 |
| 不装进系统 site-packages | 系统 `numpy 1.17.4` 保持原样 |

**自检方式**：`/detector` 启动时会打印实际加载的 numpy 版本与路径：

```
[detector] numpy 1.21.6 @ /…/lib/m4_deps/numpy（隔离目录 /…/lib/m4_deps）
```

而其他节点（`/cluster`、`/camera_node`、`/visual_tracker` 等）打印出来的仍是
系统 `1.17.4`。**两相对照即可确认隔离生效。**

## 5. 隔离性验证记录（虚拟机实测，**全部通过**）

| 验证 | 命令 / 位置 | 实测结果 |
|---|---|---|
| 系统 numpy 未被改动 | `python3 -c "import numpy;print(numpy.__version__)"` | ✅ `1.17.4 @ /usr/lib/python3/dist-packages` |
| 只有 `/detector` 用隔离 numpy | 节点启动日志 | ✅ `numpy 1.21.6 @ .../lib/m4_deps/numpy（隔离生效）` |
| 非视觉节点用系统 numpy | `/visual_tracker`、`camera_node`（只注入 `lib/`） | ✅ `1.17.4` |
| **`cv2` 未被遮蔽** | 节点内 `import cv2` | ✅ `4.2.0 @ /usr/lib/python3/dist-packages`（与 `cv_bridge` 一致） |
| 基线依赖回归 | `python3 -m pytest test -q` | ✅ **234 passed** |
| **真实推理可用** | `detector_node` + `yolov8n.pt` | ✅ `/detections` 输出真实 bbox |

⚠️ **这里踩到过一个"静默失效"**：初版把 `sys.path.insert(0, m4_deps)` 放在
`import rospy` **之后**，而 `rospy` 导入时**就已经 `import numpy`** —— 注入完全无效，
节点静默退回系统 `1.17.4`，直到 ultralytics 内部才炸出
`TypeError: integer argument expected, got float`。

> **修复：路径注入必须早于 `import rospy`**，并且自检要"会报错"而不是只打印版本。
> 详见 `04_虚拟机实跑记录.md` §7.2.3 与 §13.1。

## 6. 回滚方式

该方案**不改动系统任何东西**，回滚只需删除目录：

```bash
rm -rf <工程根>/catkin_ws/src/uav_tracking/lib/m4_deps
```

删除后 `/detector` 会回到「未安装 ultralytics」状态（照常运行、发空
`/detections`），**不影响其他任何节点**。

> 建议把 `lib/m4_deps/` 加入 `.gitignore`（体积大、可由上述命令重建）。
