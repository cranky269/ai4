# M4 交付说明 · 五、上机操作指南（从零跑起来）

> 面向：**第一次上手的同学**。照着敲就能把 M4 跑起来并看到结果。
> 全程在**虚拟机内部**操作，不需要任何外部工具。

---

## 0. 先搞清楚这套东西是什么

M4 是三个 ROS 节点，串成一条链：

```
/camera_node  ──/camera/image_raw──>  /detector  ──/detections──>  /visual_tracker
   相机驱动                              YOLO 检测                    BoT-SORT 跟踪
                                                                └──>/visual/tracks
```

| 节点 | 作用 | 订阅 | 发布 |
|---|---|---|---|
| `/camera_node` | 把图像源（视频/图片/USB/仿真）发到契约话题 | — | `/camera/image_raw` |
| `/detector` | 检测目标（YOLOv8/v11） | `/camera/image_raw` | `/detections`（+ 调试图） |
| `/visual_tracker` | 给目标分配稳定 ID、算面积比 | `/detections` + `/camera/image_raw` | `/visual/tracks` |

**关键约定**：三个节点**每帧必发**，没有目标就发**空数组**（不是不发）。
因为下游 `/state_machine` 靠"消息到达"数帧，少一帧就会误判。

> `/visual_tracker` 同时订阅图像，是为了用**图像的实际尺寸**算 `area_ratio`；
> 图像还没到时用 `~width` / `~height` 参数兜底（默认取模块常量 `DEFAULT_FRAME_SIZE`）。
> 可用 `_use_image:=false` 关掉图像订阅。

## 1. 前置：每开一个新终端，先做这两件事

在虚拟机里按 `Ctrl + Alt + T` 打开终端，然后**每次都先执行这两行**：

```bash
source /opt/ros/noetic/setup.bash
source ~/桌面/ai4/catkin_ws/devel/setup.bash
```

**为什么要做**：

| 那行命令 | 作用 | 不做的后果 |
|---|---|---|
| `source /opt/ros/noetic/setup.bash` | 让 shell 认识 `roscore` / `rosrun` / `rostopic` 等命令 | 敲 `rosrun` 会说"命令未找到" |
| `source ~/桌面/ai4/catkin_ws/devel/setup.bash` | 让 shell 认识你们自己的包 `uav_tracking` | 敲 `rosrun uav_tracking ...` 会说"找不到包" |

> ⚠️ **这是新手第一大坑**：99% 的"找不到节点/找不到包"都是漏了这两行。
> 每开一个新终端都要重新做，因为它只对当前终端生效。

**验证一下**（能执行、不报"command not found"就对了）：

```bash
rosnode list
```

## 2. 方式一：多终端手动启动（**推荐先用这个，能看清每一步**）

需要 **4 个终端**，每个终端都先做第 1 节的两行 `source`。

### 终端 1 —— 启动 ROS 主节点

```bash
roscore
```

**你应该看到**：

```
started core service [/rosout]
```

**这个终端不要关**，它是整个系统的中枢。

### 终端 2 —— 启动相机

```bash
rosrun uav_tracking camera_node.py _source:=video _video_path:=/tmp/e2e_test.avi _fps:=15
```

**你应该看到**：

```
[camera_node] ready: source=video fps=15.0 out=/camera/image_raw
```

**参数说明**（`_名字:=值` 是 ROS 传参的写法）：

| 参数 | 本例取值 | 含义 |
|---|---|---|
| `_source` | `video` | 图像来源：`video` / `image` / `usb` / `gazebo` |
| `_video_path` | `/tmp/e2e_test.avi` | 视频文件路径（`_source:=video` 时用） |
| `_fps` | `15` | 出图频率（Hz） |
| `_loop` | 默认 `true` | 播完是否循环 |

> 没有测试视频？见第 6 节"自己造测试素材"。

### 终端 3 —— 启动检测

```bash
rosrun uav_tracking detector_node.py
```

**你应该看到**（**当前还没装 YOLO 模型时会这样**）：

```
[ERROR] [detector] 推理失败: [detector] 未安装 ultralytics，无法进行检测；...
```

**这是预期行为，不是崩溃**：节点照常运行、照常按帧率发空的 `/detections`。
等 `ultralytics` 批准装上后，这里就会打印真实检测结果。

### 终端 4 —— 启动跟踪

```bash
rosrun uav_tracking visual_tracker_node.py
```

正常的话**没有任何输出**（它只在出错时才打印）。

## 3. 看结果（再开一个终端，做第 1 节的两行 `source`）

| 命令 | 你会看到什么 | 说明 |
|---|---|---|
| `rosnode list` | `/camera_node` `/detector` `/visual_tracker` | 三个节点都活着 |
| `rostopic list` | `/camera/image_raw` `/detections` `/visual/tracks` | 三个契约话题都在 |
| `rostopic hz /detections` | `average rate: 15.0xx` | **节拍稳定 15 Hz**（`Ctrl+C` 退出） |
| `rostopic echo /detections` | `targets: []` | **空数组**（没装模型所以没目标） |
| `rqt_graph` | 节点连接图 | 一眼看清谁连谁 |
| `rqt_image_view /camera/image_raw` | **实时画面** | 能看到视频在播（窗口小，拖边缘放大） |

### 最值得做的一次实验：验证「空也发」

开**两个**终端：

- 终端 A：`rostopic hz /detections` → 一直显示 **15 Hz**
- 终端 B：`rostopic echo /detections` → 内容一直是 **`targets: []`**

**结论**：没有目标时，话题**照样按帧率发空消息**，而不是静默。
这就是状态机连续帧计数不会断档的前提 —— 也是我在文档里承诺的硬约束。

## 4. 方式二：一键后台启动（日常用，省终端）

```bash
cd ~/桌面/ai4
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash

nohup roscore > /tmp/roscore.log 2>&1 &
sleep 3
nohup rosrun uav_tracking camera_node.py _source:=video _video_path:=/tmp/e2e_test.avi _fps:=15 > /tmp/cam.log 2>&1 &
sleep 2
nohup rosrun uav_tracking detector_node.py > /tmp/det.log 2>&1 &
sleep 3
nohup rosrun uav_tracking visual_tracker_node.py > /tmp/tracker.log 2>&1 &
sleep 3

rosnode list
```

### 全部关掉

```bash
pkill -f camera_node; pkill -f detector_node; pkill -f visual_tracker_node
pkill -f rqt_image_view; pkill -f rqt_graph; pkill -f rosmaster
```

> `pkill -f 关键字` = 杀掉所有命令行里含该关键字的进程。

## 5. 自己跑测试

```bash
cd ~/桌面/ai4
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash        # ← 两个都要 source！原因见下

# 全部单元测试（227 项）
python3 -m pytest test -q

# 只跑 M4 的（88 项）
python3 -m pytest test/camera test/detector test/visual_tracker -q
```

### E2E（端到端，会真的起节点跑数据）

```bash
bash test/camera/e2e_test/run_e2e.sh            # 相机：video 源 + image 源
bash test/visual_tracker/e2e_test/run_e2e.sh    # 跟踪：有目标 + 无目标
bash test/detector/e2e_test/run_e2e.sh          # 检测：链路 + 空也发
```

每个脚本最后一行会打印 `E2E RESULT: PASS` 或 `FAIL`。
**这三个脚本从任意目录、任意终端都能直接跑**（内部自动推导路径和环境）。

> ⚠️ **跑测试前必须 source 两个 `setup.bash`**。
> 只 source 第一个的话，`uav_tracking.msg` 导不进来，
> **节点壳测试会被静默跳过**（输出 `7 passed, 4 skipped`），看着像全绿其实少了 41 个用例。

## 6. 自己造测试素材

相机需要一段视频或一张图片。用仓库自带的脚本生成：

```bash
cd ~/桌面/ai4
python3 test/camera/e2e_test/make_media.py /tmp 15.0
```

产出：

| 文件 | 内容 |
|---|---|
| `/tmp/e2e_test.avi` | 320x240 / 15 fps / 90 帧，含**移动的红方块**与逐帧帧号 `F000`→`F089` |
| `/tmp/e2e_test.png` | 最后一帧的静态图 |

有了素材就能用第 2 节的命令启动相机了。

## 7. 常见报错对照表

| 报错 | 原因 | 解决 |
|---|---|---|
| `rosrun: command not found` | 没 source ROS | 执行第 1 节第一行 |
| `[rospack] Error: package 'uav_tracking' not found` | 没 source `devel/setup.bash` | 执行第 1 节第二行 |
| `Unable to communicate with master` | `roscore` 没起 | 先开终端 1 跑 `roscore` |
| `[rosrun] Couldn't find executable named xxx.py` | 脚本没有可执行权限 | `chmod +x catkin_ws/src/uav_tracking/scripts/*.py` |
| `/usr/bin/env: "python3\r": 没有那个文件或目录` | 文件是 Windows 换行（CRLF） | 存成 LF 换行（Linux 下用 `dos2unix`） |
| `ROS_DISTRO：未绑定的变量` | 脚本里 `set -u` 和 `source setup.bash` 冲突 | 用仓库里的 `run_e2e.sh`（已修） |
| `[detector] 推理失败: 未安装 ultralytics` | **依赖未安装（当前正常状态）** | 等群里批准后装 `~/m4_deps` |
| `[camera_node] 无法打开 video 源` | 视频文件路径不对 | 用第 6 节重新生成，确认路径 |
