> 记录人：M4 负责人　　组长确认时间：2026-10-06
> 范围：**设计文档**（`design/数据类型.md`、`design/函数接口.md`）

---

## 缺陷 1：同一份「检测结果」有两个名字

### 现象

文档里对同一个数据结构用了**两个不同的名字**，而代码里只实现了一个。

| 出处 | 用的名字 |
|---|---|
| `数据类型.md` 1.1（ROS 消息 `DetectedTarget.msg`） | `DetectedTarget` |
| **`数据类型.md` 2.4（纯数据结构）** | **`Detection`** |
| **`函数接口.md` 4.1 签名** | **`def detect(image) -> list[Detection]`** |
| **`函数接口.md` 5.1 签名** | **`def track(detections: list[Detection]) -> list[VisualTrack]`** |
| `code/datatypes.py` 实际定义 | 只有 `DetectedTarget`（**没有 `Detection`**） |
| 组长既有代码 `state_machine.py` / `cluster` 系列 | 用的是 `DetectedTarget` |

### 影响

若把 `Detection` 建成一个**独立的新类**，则：

- `detect()` 返回的 `Detection` 与状态机期望的 `DetectedTarget` 会是**两个不同的类**；
- 跨模块传参虽然字段同名，但 `isinstance` 判定失败，后续扩展容易踩坑。

### 组长判定（2026-10-06）

> **判断正确。理论上只有 `DetectedTarget` 有用，这两个是一个作用。**
> 把设计方案中的 `Detection` 改成 `DetectedTarget`。

### 处理结论

| 侧 | 处理方式 | 状态 |
|---|---|---|
| **设计方案** | 将 `数据类型.md` 2.4 与 `函数接口.md` 4.1 / 5.1 中的 `Detection` 统一改为 **`DetectedTarget`** | 待组长在文档侧修改 |
| **M4 代码** | 去掉此前的本地别名，**统一使用 `DetectedTarget`**（与组长既有代码一致） | ✅ 已完成 |
| `datatypes.py` | **未改动**（组长既有文件，本来就只有 `DetectedTarget`，无需改） | ✅ 零改动 |

> 📌 **代码侧落实位置**（均只用 `DetectedTarget`）：
>
> ```python
> # code/detector.py
> from datatypes import DetectedTarget
> def detect(image: np.ndarray) -> list[DetectedTarget]: ...
>
> # code/visual_tracker.py
> from datatypes import DetectedTarget, VisualTrack
> def track(detections: list[DetectedTarget],
>           image: np.ndarray | None = None) -> list[VisualTrack]: ...
>
> # catkin_ws/src/uav_tracking/scripts/visual_tracker_node.py
> from datatypes import DetectedTarget
> ```
>
> 组长既有代码 `state_machine.py:100` 写的也正是
> `detections: list[DetectedTarget]`，**两侧现已完全一致**。
