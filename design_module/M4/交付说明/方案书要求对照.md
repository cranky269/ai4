## 一、方案书对"视觉感知模块"的原话

> **2. 视觉感知模块**
> **功能**：接收无人机实时第一人称视频流（FPV），在画面中实时检测、分类并锁定目标
> （如特定人物或车辆）。
> **技术手段**：**YOLOv8/v11**：用于目标检测，提取目标二维像素坐标和边界框大小；
> **BoT-SORT**：多目标跟踪，赋予目标唯一 ID。
> **任务要求**：利用 AI 快速生成调用模型、处理图像矩阵、**在画面上绘制 Bounding Box
> （YOLO 边界框）**并输出坐标数据。

## 二、逐条对照

| # | 方案书要求 | 我的实现 | 判定 |
|---|---|---|---|
| 1 | **接收 FPV 视频流** | `/camera/image_raw` 为输入；`camera_node` 支持 `video`/`image`/`usb`/`gazebo` 四种源 | ✅ |
| 2 | **实时检测、分类** | `/detector`（YOLO）输出 `class_id` + `confidence` + `bbox` | ✅ |
| 3 | **锁定目标** | `/visual_tracker` 输出**唯一 ID**；`/state_machine` 据此判 `VISUAL_LOCK`（实测已触发） | ✅ |
| 4 | **技术手段：YOLOv8/v11** | 用 **YOLOv8n**（`ultralytics` 实现，**v11 同库同接口**，换权重即可） | ✅ |
| 5 | **技术手段：BoT-SORT** | 实现 **BoT-SORT 核心**：卡尔曼滤波 + **两阶段关联** + 贪心 IoU 匹配；ReID/GMC 按组长要求暂缓 | ✅ |
| 6 | **提取目标二维像素坐标和边界框大小** | `DetectedTarget.bbox`（xywh）；`VisualTrack.area_ratio`（面积占比，供下游判远近） | ✅ |
| 7 | **在画面上绘制 Bounding Box** | `/detector/debug_image` 发布**已画好 bbox + 类别 + 置信度**的调试图 | ✅ |
| 8 | **输出坐标数据** | `/detections`、`/visual/tracks`（契约话题，见《数据类型.md》） | ✅ |

### ⚠️ 第 7 条要特别说一句

**「在画面上绘制 Bounding Box」是方案书明确写的交付物**，不是可选项。
所以 `/detector/debug_image`（调试图）**必须开**（`~publish_debug` 默认 `true`）。

> 之前我曾想通过关掉它来省算力 —— **实测影响只有约 1%**（`imgsz=320`：
> 22.14 → 22.33 FPS），且它是方案书要求的交付物，**故保持开启**。

## 三、切换条件（方案书写得很具体，逐条核）

> **切换条件**：设定当 YOLO 识别到"敌机" **> 80%**，且 Bounding Box 的像素面积
> **大于画面总面积的 2%**（模拟距离逼近至百米），并**连续 N 帧**保持该状态时，
> 触发末端精细拦截。

| 参数 | 方案书 | 实现位置 | 判定 |
|---|---|---|---|
| 置信度阈值 | **> 80%** | `/state_machine` 的 `conf=0.80` | ✅ 一致 |
| 面积阈值 | **> 2% 画面** | `/state_machine` 的 `area=0.020` | ✅ 一致 |
| 连续帧数 | **连续 N 帧** | `/state_machine` 的 `N`（当前 **3**） | ✅ 但 **N 的具体值方案书未给** |
| 帧数来源 | — | 由 M4 的 `/detections`、`/visual/tracks` **到达节拍**计数 | ✅ 所以 M4 的「空也发」是前提 |

> **注意**：`conf` / `area` 阈值和 `N` **属于状态机（他人模块）**，M4 只保证
> **数据以稳定节拍到达**（「空也发」契约）—— 这正是方案书"连续 N 帧"能实现的前提。

### 安全熔断

> **安全熔断**：当视觉连续 **M 帧**丢失目标，状态机需自动退"雷达引导"模式重新搜索。

| 方案书 | 实现 | 判定 |
|---|---|---|
| 连续 M 帧丢失 → 退回雷达 | `/state_machine` 的 `M`（当前 **3**）；M4 保证**丢失时仍发布空消息**（不然状态机"收不到"而非"收到没有"） | ✅ |

## 四、验收标准（方案书原表）

| 评估维度 | 方案书验收标准 | 与 M4 的关系 |
|---|---|---|
| 1. 点迹关联与引导 | 仿真中稳定滤除杂波、断续点迹连成平滑航迹、引导至百米范围 | 雷达模块（非 M4） |
| **2. 视觉跟踪与拦截** | 「**雷达到视觉的切换平滑无卡顿**，视觉锁定期 PID 跟踪稳定，成功在仿真与实机中完成末端追踪」 | **M4 主责** |
| 3. 技术总结 | 分析视觉与雷达的权重分配与融合策略、实机误差来源 | 结项文档（组长已定"权重融合暂缓实现"） |

**关于"平滑无卡顿"**：

- 方案书用词是**定性**的（"平滑""无卡顿""稳定"），**没有给帧率数字**；
- M4 侧对应的**可量化证据**：`id` 跨帧稳定不跳变（E2E 实测 60 帧恒为同一 id）、
  「空也发」保证节拍不断、节点实测帧率（`imgsz=320 → 22.1 FPS`）；
- 所以**"够不够快"应按联调时的实际观感/整定来定**，而不是对某个固定 FPS。

> **勘误连带**：本仓库曾自行写着"验收基线 ≥15 FPS"。经核对
> **方案书 + 拆解文档 + 函数接口.md 全文，均无任何帧率数字**，
> 该数值已从 `README.md`、`docs/05`、`docs/06`、`docs/07`、`04` 中勘误。
