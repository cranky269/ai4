## 问题 2：E2E 断言缺少「接口格式」校验

**位置**：各模块 `e2e_test/check_*.py`

**现象**：现有断言主要校验「话题在流 / 消息条数 / 数值范围」，
但**没有校验 bbox 的坐标约定**。而本项目最容易出的接口事故正是：

> 把 `(x, y, w, h)`（左上角 + 宽高）写成了 `(x1, y1, x2, y2)`（左上 + 右下）

一旦搞混，`w` / `h` 会变成负数或数值离谱，**但消息本身仍然"合法"**，不易察觉。

**可修复方式**（M4 已在 `test/detector/e2e_test/check_detections.py` 里加了 3 条）：

1. `w > 0 且 h > 0` —— 搞混时宽高变负，立刻暴露；
2. `x >= -eps 且 y >= -eps` —— 左上角不应为负；
3. `x + w <= frame_w * 1.2` —— `x2` 误填成 `x` 时会越界。

雷达链的 `check_centroid.py` 可照加一条坐标范围合理性断言。

**组长判定（2026-10-06）**：

> **可以改你自己的，但是别改别人的。**

**M4 侧**：**未改动**任何他人文件；上述 3 条断言只加在 M4 自己的断言脚本里。

## 问题 3：三个已有 E2E 脚本在 `set -u` 下 source ROS 会失败

**位置**：同上三个 `run_e2e.sh`（若其中也写了 `set -u`）

**现象**：脚本开头 `set -u`（引用未定义变量即报错），而
`/opt/ros/noetic/setup.bash` 加载的 profile 脚本**会引用 `ROS_DISTRO` 等
"此刻尚未定义"的变量** —— 两者冲突，`source` 直接中断：

```
1.ros_distro.sh: 行 3: ROS_DISTRO：未绑定的变量
```

**影响**：从**干净终端**直接跑脚本会立刻失败，且报错信息与业务无关，容易误判。

**可修复方式**（M4 已采用）：

```bash
set +u
source /opt/ros/noetic/setup.bash
source "$WS/devel/setup.bash"
set -u
```

**组长判定（2026-10-06）**：与问题 1 同批 —— 属他人脚本，**M4 不改**。

**M4 侧**：只改了**自己**的三个 `run_e2e.sh`（见
`04_虚拟机实跑记录.md` §12），并在修复后从干净 shell 复验通过。
