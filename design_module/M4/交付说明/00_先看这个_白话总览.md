## 一、一句话说清 M4

**整个项目**：雷达先发现目标 → **视觉锁死它** → 控制无人机撞上去。

**M4 就是中间那一步「视觉锁死它」。**
输入是**摄像头画面**，输出是**"目标在画面的哪个位置、多大、编号几"**。

---

## 二、M4 里有 3 个程序（各自一句话）

| 程序（节点名） | 大白话 | 吃什么 → 吐什么 |
|---|---|---|
| `camera_node` | **相机驱动**。仿真时相机插件直接出图，就**轮不到它**；真机/USB/本地视频才用它 | 视频 / 图片 / USB 相机 → `/camera/image_raw` |
| `detector` | **看每一帧，说"这帧里有东西"** | 图像 → `/detections` |
| `visual_tracker` | **把连续几帧串起来，说"这些都是同一个目标，编号 1"** | `/detections` → `/visual/tracks` |

### 检测 和 跟踪 的区别（这是最关键的一点）

- **检测**：只看**一张**照片 → "有个东西在这儿"
- **跟踪**：看**一串**照片 → "**还是刚才那个东西**，它正在往右移"

> **为什么要跟踪？** 因为只有**编号稳定**，下游才知道"这是同一个目标"，
> 才能算它的速度、预测它往哪飞、判断该不该撞。
> 如果每帧都重新编号，下游看到的就永远是"新目标"，没法锁。

### 再往下一环（不是 M4 的活儿，但要知道）

`/visual/tracks` 会送给 **`/state_machine`（状态机）**，由它判断
**"够不够锁定"**，够了就切到视觉通道 → 控制无人机。
在虚拟机里跑，你能看到这一句：

```
[state_machine] RADAR_GUIDE -> VISUAL_LOCK
```

**看到这句 = 整条链真正打通了。**

### 方式 C：手动开 3 个终端看效果（**给人看/演示用这个**）

**终端 1 —— 假装是相机**（用一张现成图片当画面，30 帧/秒）

```bash
rosrun uav_tracking camera_node.py _source:=image \
    _image_path:=/home/demo/m4_assets/bus.jpg _fps:=30
```

**终端 2 —— 检测**

```bash
rosrun uav_tracking detector_node.py _model_path:=/home/demo/m4_assets/yolov8n.pt \
    _conf_thres:=0.4 _imgsz:=320 _device:=cpu
```

**终端 3 —— 跟踪**

```bash
rosrun uav_tracking visual_tracker_node.py
```

**终端 4 —— 看结果**

```bash
rostopic echo /visual/tracks
```

**终端 5 —— 看图（可选，最直观）**

```bash
rosrun rqt_image_view rqt_image_view /detector/debug_image
```

> 不想敲这么多？先跑 `roscore` 也可以，但上面这些脚本会自己处理。
> **关掉的时候**：各终端按 `Ctrl+C`，不要直接叉窗口。

## 四、怎么知道"跑对了"（看这个就行）

在**终端 4** 里，如果出现**这样的内容**，就是对的：

```
tracks:
  -
    id: 1
    bbox: [46.9, 394.4, 185.3, 509.2]
    area_ratio: 0.1078
  -
    id: 2
    bbox: [6.4, 227.6, 793.9, 525.1]
    area_ratio: 0.4765
```

**三个关键点**：

| 看到什么 | 说明什么 |
|---|---|
| 有 `id:` | ✅ 跟踪在给目标编号 |
| `id` 连续几秒**不变** | ✅ 跟踪稳定（**这是最难做对的一点**） |
| 有 `area_ratio:` | ✅ 目标大小算出来了（下游靠它判断"够不够近"） |

**如果 `tracks:` 下面是空的（`[]`）** —— **也是正常的**，表示"这一帧没看到目标"。
**这是我们故意设计的**（叫"空也发"）：**没目标也要发消息，不能闷不吭声**，
否则下游会以为"程序死了"。

> 所以：**空的也是有在正常工作**，关键看话题**有没有在持续出消息**。

## 五、出问题怎么办（对照着看）

| 现象 | 八成是什么 | 怎么办 |
|---|---|---|
| `rosrun` 说 `Couldn't find executable` | 文件没有执行权限 | `chmod +x /home/demo/桌面/ai4/catkin_ws/src/uav_tracking/scripts/*.py` |
| 报 `python3\r: 没有那个文件或目录` | 文件换行符变成 Windows 格式了 | 说明有人在 Windows 上编辑过，用 LF 重新保存 |
| `/detections` 一直是空的 `targets: []` | ①没装视觉依赖 ②模型路径不对 ③图里真没目标 | 看终端里的日志，会写清楚 |
| 日志出现 `numpy 1.17.4`（而不是 `1.21.6`） | **依赖隔离失效了** | 这是已知坑，看 `04` §13.1；正常应显示 `numpy 1.21.6 @ .../lib/m4_deps` |
| 报 `推理失败: integer argument expected, got float` | 同上（隔离失效的连带症状） | 同上 |
| 一切正常但**很卡** | CPU 只有 4 核，`imgsz` 取大了 | 把 `_imgsz` 从 640 改成 **320**（帧率能翻一倍多） |
| `Unable to communicate with master!` | 没起 `roscore` | 起一个，或直接跑方式 A 的一键脚本 |

## 六、别人问起来怎么答（**照念就行**）

### Q：你这模块做完了吗？
> **代码和功能已经做完了，也在虚拟机里真跑通了**：真图 → 真 YOLO 检测 → 真跟踪 →
> 状态机切入 `VISUAL_LOCK`。单元测试 **234 项全过**，三个端到端测试全 PASS。
>
> 还缺的是**外部条件**：无人机的**专用模型权重**（我现在用通用 COCO 权重验证管线）、
> 仿真侧相机插件、真机 USB 相机（虚拟机里没设备）。

### Q：能跑多快？
> **看 `imgsz` 我设多少**（4 核 CPU 实测，节点口径）：
> `320 → 22 帧/秒`、`416 → 16~18`、`640 → 10`。
> **按相机帧率来选**就行 —— 设计文档要求的是"**随相机帧率**发布"，没有绝对指标。

### Q：改了组长的东西吗？
> **没有，组长原有文件一行都没改。** 只新增了文件；
> 另有一个 `requirements.txt` 是**追加注释**（规则明确允许，且行为完全不变）。

### Q：数据/测试可信吗？
> 都在 `04_虚拟机实跑记录.md` 里，**每条结论都带实测命令和原始输出**。

## 七、组长回答那 6 个问题之后，你怎么办

| 他说的 | 你就这么接 |
|---|---|
| **切换延迟含 3 帧计数** | 「明白，那视觉帧率要提，我把 `imgsz` 再降一档重新测帧率和延迟」 |
| **切换延迟不含计数** | 「明白，那现在的默认值就够用，我把这条口径记进文档」 |
| **有专用权重** | 「好，把 `.pt` 文件给我，我换上重新测检出率」 |
| **没有专用权重** | 「那我继续用通用权重验证管线，**检出率这条先不作为验收依据**」 |
| **相机帧率 X Hz** | 「收到，我按 X Hz 定 `imgsz`，跑完把实测帧率贴出来」 |
| **GMC 要补** | 「好，我按 BoT-SORT 的 GMC 补，补完重新跑跟踪的端到端测试」 |
| **依赖给下载脚本** | 「已经在 `组长确认冲突库下载说明文档.md` 里写好分步命令了，队友照抄即可」 |

> **一句话原则**：他给**数字/文件**，你就说"我拿到就重测"；
> 他说**不用管**，你就说"好的，这条我记进文档里"。
> **不确定的，就说"我看一下文档再确认"** —— 这份文档（和 `03`）就是给你兜底的。
