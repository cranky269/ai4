# M4 实时演示（肉眼可看版）

这个目录是给**人盯着看**用的 —— 不是跑完就退出的测试，而是把 M4 整条链
**一直开着**，直接在桌面上显示真实检测结果。

```bash
cd ~/桌面/ai4/test/M4_现场验证/实时演示
bash m4_live.sh          # 启动（约 1 分钟，跑完不退出）
bash m4_live.sh stop     # 停止
```

## 一个窗口看全

启动后桌面右侧会出现一个窗口 **`M4 LIVE /detector/debug_image`**：

```
┌──────────────────────────────────────┐
│ M4 LIVE /detector/debug_image        │
├──────────────────────────────────────┤
│ STATE  : VISUAL_LOCK (from log)      │ ← 绿色 = 视觉锁定成功
│ DET    : 4 target(s), max conf 0.85  │
│ TRACKS : 4  ids=[1, 2, 3, 4]         │
│ AREA   : 0.108 0.477 0.066 0.079     │
│ RATE   : 5.0 Hz  img=(1080, 810, 3)  │
│                                      │
│      ┌────────────────────┐          │
│      │  真实照片 + 绿色检测框 │          │
│      └────────────────────┘          │
└──────────────────────────────────────┘
```

**画面里的框是 `/detector` 节点真画上去的**（发布在 `/detector/debug_image`），
不是后期合成的。

## 三个文件

| 文件 | 作用 |
|---|---|
| `m4_live.sh` | 一键：起 roscore + 四个节点 + 开窗口；`m4_live.sh stop` 停 |
| `live_view.py` | 实时画面窗口（订阅 `/detector/debug_image` 等，把状态叠在画面上） |
| `dashboard.py` | 纯终端版状态面板（不想开图形窗口时可以只用它） |
| **`live_stream.py`** | **浏览器直播服务**：把画面/状态/日志用 HTTP 播出去（见下节） |
| `start_stream.sh` | 启动直播服务（`bash start_stream.sh [端口]`） |
| `restart_nodes.sh` | 只重启四个节点、**不动 roscore** → 直播时能看到整条链逐步起来 |
| **`make_moving_clip.py`** | **用真图合成"无人机逼近目标"的视频**（目标逐渐变大 + 位置漂移），给 `video` 源用 |
| `get_assets.sh` | 下载模型与测试图到 `assets/`（多备用源） |
| **`verify.sh`** | **一键自证**：ROS 原始数据 / 网页数据 / 时间戳 三方对账，输出 PASS/FAIL |
| **`set_camera_source.sh`** | 单独换 `camera_node` 的源（图片/视频），**手工验证用** |

日志目录：`/tmp/m4_live/`（四个节点各自的 log + viewer 的 log）

## 两种相机源：静态图 vs 动态视频

| | `demo.sh`（默认） | `demo.sh moving`（推荐） |
|---|---|---|
| `camera_node` 参数 | `_source:=image _image_path:=bus.jpg` | `_source:=video _video_path:=bus_moving.mp4` |
| 画面 | **同一张照片反复发** | **真照片 + 取景框运动**（缩放 + 横移） |
| `area_ratio` | **恒定不变** | 一直在变 |
| 航迹 ID | 稳定（但说明不了什么） | 稳定 = **跟踪没跟丢、没换 ID** |
| 适合 | 快速自检 | **演示 / 观察** |

### 为什么只用「真照片 + 取景框运动」，不做合成贴片

跟踪器（以及下游 PID）**只看图像像素**。目标在图像里怎么移动，
它**无法也不必区分**"是目标在动"还是"相机在动" —— 两者在图像坐标上完全等价。

而**本任务里相机一定在动**（无人机飞向目标），所以「真实照片 + 取景框运动」
**恰好就是任务里的真实情形**。

> ❌ **曾经做过一个"sprite"模式**：把照片裁一块当目标贴片贴在合成背景上滑。
> 看着"目标在动"，但引入了**现实中不存在的假特征**（硬边矩形、重采样模糊），
> 导致检出断续、状态机掉锁 —— **属于自欺欺人，已删除**。

三种运动（同一张真照片的取景框运动）：

| 模式 | 画面里看到什么 | 主要检验 | 对应 PID 的量 |
|---|---|---|---|
| `approach` | 目标**变大**，中心基本不挪 | 尺度变化 | `area_ratio` → 接近速度 |
| `sweep` | 目标**在画面里横移**，大小不变 | 方向变化 | `bbox` 中心 → `yaw_rate` |
| `both`（= `moving`） | 两者一起 | 两维 | 两者 |

生成视频（150 帧 / 10 fps / 15 秒，循环）：

```bash
python3 make_moving_clip.py assets/bus_moving.mp4 150 10 both   # 默认
python3 make_moving_clip.py 出.mp4 150 10 sweep                 # 也可 approach
```

### ★ 视频只是"给人看"，验收证据在 E2E

| 证据 | 内容 |
|---|---|
| 单测 `test_id_stable_across_moving_frames` | 目标连续移动时 ID 保持不变 |
| 单测 `test_lost_then_recovered_keeps_id` | 丢失后恢复，ID 不变 |
| 单测 `test_two_targets_get_distinct_ids_and_do_not_swap` | 两目标不互换 ID |
| **E2E 阶段A** | 假检测源**每帧位移 4/3 像素**，断言「**框确实在动** + ID 不变 + `area_ratio` 自洽」 |

```bash
cd ~/桌面/ai4 && bash test/visual_tracker/e2e_test/run_e2e.sh
```

## 浏览器里看（推荐，不用盯着虚拟机）

```bash
bash m4_live.sh            # ① 起 M4 节点（含图形窗口）
bash start_stream.sh       # ② 起直播服务（默认 8090 端口）
```

然后在**宿主机浏览器**打开：

```
http://192.168.183.128:8090/
```

页面上三块，全部每秒刷新：

| 区域 | 内容 |
|---|---|
| 左 | 带检测框的画面（MJPEG 流，`multipart/x-mixed-replace`） |
| 右上 | 当前状态 / 目标数 / 最高置信度 / 航迹 ID / area_ratio / 帧率 / 画面尺寸 |
| 右下 | 四个节点的日志实时尾巴 |
| 顶栏右 | 画面状态提示 + `原图` 链接 |

**看单帧细节**：点顶栏的 `原图` → 新标签打开当前帧的**原始分辨率 JPEG**（`/snapshot`，
不经任何浏览器缩放）。想存下来就右键另存。

> ★ **为什么没有"把图放大"的按钮**：这帧是 JPEG 质量 80 编出来的，像素信息就那么多，
> 整体放大只会把马赛克一起放大 —— **放大不增加信息**。
> 画面原始 810×1080，在 900px 高的窗口里是"被缩小到 83%"，不是"太小"。
>
> 曾经做过「适应窗口 / 原始 1:1」切换按钮，**实测无价值，已删除**（用户反馈"没感觉啥用"）。

**画面空白怎么办（三条都见过）**

| 现象 | 原因 | 现在怎么办 |
|---|---|---|
| 状态/日志在动，**画面空了** | 服务端**重启过**，浏览器不会自动重连 MJPEG | **已自动处理**：页面发现 `frames` 回退就重新建立连接，提示栏显示 `画面: 已重连（服务端重启过）`；也可手动 `Ctrl+F5` |
| 打开就是空白（老内核） | 该浏览器**不渲染 `multipart/x-mixed-replace`**（实测虚拟机自带的旧 Firefox 有过） | **已自动降级**：加载后 3/6/9/12 秒仍没拿到第一帧，自动切成 `/snapshot` 轮询（4 fps），提示栏显示 `画面: 轮询兜底（…）` |
| 画面停住不动 | 流断开且浏览器不重连 | **已自动处理**：`/status` 的 `frames` 连续 5 秒不变即降级轮询 |

> **注意**：页面响应带 `Cache-Control: no-store`。如果改了页面却看不到变化，
> 先怀疑浏览器缓存 —— 强制刷新（`Ctrl+F5`）。
>
> 排查时**先分清哪一端的问题**：
> - 服务端：宿主机 `curl -s -m6 http://192.168.183.128:8090/stream.mjpg | head -c 300 | xxd`
>   —— 正常应看到 `--frame\r\nContent-Type: image/jpeg\r\nContent-Length: …\r\n\r\n\xff\xd8\xff`
> - 浏览器端：打开 `http://192.168.183.128:8090/snapshot` —— 能显示就说明浏览器没问题，是 MJPEG 那条路
> - 实测数据（正常时）：6 秒收到 113 帧 / 20 MB，`--frame`、`Content-Length`、JPEG 头各 113 次

其它端点：

| 路径 | 说明 |
|---|---|
| `/` | 上面那个页面 |
| `/stream.mjpg` | 纯 MJPEG 流（可嵌到任何页面 `<img src="...">`） |
| `/status` | 状态 JSON（页面就是轮询它） |
| `/snapshot` | 抓一张当前帧（原始分辨率，`Cache-Control: no-store`） |

**想看"整条链起来的过程"**：另开一个终端跑

```bash
bash restart_nodes.sh
```

它会停掉四个节点再按正确顺序拉起（**保留 roscore**，所以直播服务不会掉），
你在页面上就能看到：画面停住 → `camera ready` → `detector ready` → `tracker ready`
→ `state_machine: RADAR_GUIDE -> VISUAL_LOCK`。

> 为什么不用 `rqt_image_view` / `image_view`：这个镜像里没装。
> `live_stream.py` 只用 stdlib + cv2 + rospy，**零额外依赖**。

## 几个已知点（脚本里都处理了，但值得知道）

### 1. 分辨率会跟着宿主机窗口变

VMware 的「自动适应」会**按宿主机的窗口尺寸改 guest 的分辨率**。
所以我一开始把虚拟机的 VMware 窗口拖小，guest 分辨率掉到过 **320x200**，
窗口全跑屏幕外面，看着像"程序没开"。

`live_view.py` 里做了**每 2 秒探测一次分辨率，变了就重新摆窗口**：

```
screen=1440x900  window=489x652@(941,40)
screen changed -> 1918x878, window=598x798@(1310,40)
```

> 如果窗口不见了，先把 VMware 窗口最大化（或执行 `xrandr -s 1440x900`），
> 等 2 秒，窗口会自己回来。

### 2. `/state` 只在变化时发布

面板里的 `STATE` 优先取 `/state` 话题；**但如果面板启动得比状态跃迁晚，
就收不到**（这个话题没有 latch）。所以 `live_view.py` / `dashboard.py`
都会**从 `/tmp/m4_live/state.log` 兜底读**，显示成 `VISUAL_LOCK (from log)`。

### 3. 启动顺序不能反

`m4_live.sh` 里是**先起跟踪器、后起状态机**。反过来的话状态机会在约 1 秒内
跳到 `SEARCH/RTH` 并卡住（原因见 `../README.md` 第四节）。

### 4. 停止时用的是「行首锚定」

```bash
pkill -f "^python3 /tmp/m4demo/live"     # 只杀 viewer，不会误杀调用它的 shell
```

用普通的 `pkill -f "live_view.py"` 会**把调用它的 shell 一起杀掉**
（因为 shell 的命令行里也含这串字）。这个坑真踩过。

## 前置条件

- `lib/m4_deps` 已安装（见 `design_module/M4/交付说明/组长确认冲突库下载说明文档.md`）
- **素材在 `实时演示/assets/`**（**在工程里**）：

  | 文件 | 干什么用 |
  |---|---|
  | `assets/yolov8n.pt` | 检测模型（约 6.4 MB） |
  | `assets/bus.jpg` | 测试图（810×1080，含 3 人 1 车） |

  缺了就补：

  ```bash
  bash get_assets.sh        # 从 GitHub 下载（多个备用源）
  ```

  > ⚠️ **别再把素材放 `/tmp`**。实测踩过：素材原放在 `/tmp/m4_infer`，
  > 一次**虚拟机重启**后 `/tmp` 被清空 → `camera_node` 抛
  > `RuntimeError: 无法获取图片` → 整条链卡在 `RADAR_GUIDE`、页面上 `frames=0`。
  > `demo.sh` 现在会**自检并在缺失时自动下载**。

- 要换素材：`MODEL=... PIC=... bash demo.sh`
