# M4 实现说明（对内，给作者与 AI 看）

> 对外操作见同级目录上游的 `../模块使用文档.md`。本文只记录设计决策、实现细节、踩坑与后续方向。

## 1. 模块边界

```
/camera/image_raw ──> [detector] ──> /detections ──> [visual_tracker] ──> /visual/tracks
                                                        │
                                        /detections ──> [state_machine] ──> /state
```

- 纯逻辑放在 `code/detector.py`、`code/visual_tracker.py`，`catkin_ws/src/uav_tracking/lib/*.py` 是指向它们的软链（mode `120000`）。
- 节点壳只做 ROS 装包/拆包，不含算法逻辑。
- `/detections` 遵守「空即正常」：无目标时发布空数组而不是静默，便于下游区分「没目标」和「节点挂了」。

## 2. 依赖隔离

- 冲突库（torch 2.4.1+cpu、torchvision、ultralytics 8.4.x、numpy 1.21.6 等）全部装在
  `lib/m4`，由 `install_m4_deps.sh` 维护，详见仓库根《冲突库汇总.md》M4 段。
- **只有 `detector_node.py`** 把 `lib/m4` 插入 `sys.path`；其他节点壳只加 `lib/`，
  因此取不到隔离 numpy，系统 `numpy 1.17.4` 不被污染。
- 必须保证 `import numpy` 之前完成 `sys.path` 修改，否则 numpy 已进 `sys.modules`，隔离失效。
- `cv_bridge` 缺失时只影响调试图，不影响主链路（`try/except ImportError`）。

## 3. 检测实现

| 项 | 决策 | 理由 |
|---|---|---|
| 输入编码 | `desired_encoding="bgr8"` | 让 cv_bridge 顺手归一化 mono8 / rgb8 |
| 推理尺寸 | 默认 640，4 核 CPU 建议 320 | 320→约 2 Hz，640→约 0.5 Hz |
| 置信度阈值 | 默认 0.5（低于状态机 0.8） | 保留 0.5~0.8 区间给跟踪器做两阶段关联 |
| 调试图 | `/detector/debug_image`，可关 | 便于 rqt / image_view 直接确认「像素确实进了模型」 |
| 权重路径 | launch 里由包路径反推仓库根 | `roslaunch` 的 cwd 是 `ROS_HOME`，相对路径会被当成模型名联网下载 |

## 4. 跟踪实现

- 状态量：`(cx, cy, w, h)` + 各自速度，标准匀速卡尔曼；`area_ratio = w*h / (W*H)`。
- **两阶段关联**（BoT-SORT 思路）：
  1. 高置信检测（`track_high_thresh`）先与预测框做 IoU 位置关联，可新建航迹（`new_track_thresh`）；
  2. 低置信检测（`track_low_thresh`）只与已有航迹关联，**不新建**，避免虚警起航迹。
- 丢帧容忍：`track_buffer=30` 帧内保持 ID；超过则回收。
- 画面尺寸优先取实际图像（`use_image=true`），取不到时用配置里的 640×480 兜底。
- 参数集中在 `config/visual_tracker.yaml`。

## 5. 状态机

- 判据：连续 `N/M/K = 3/3/5` 帧检测、置信度 `>= 0.8`、`area_ratio >= 0.02`。
- 跃迁：`RADAR_GUIDE → VISUAL_LOCK`（视觉锁定后雷达丢失也保持）。
- 0.8 的门限是有意高于 detector 的 0.5，避免低置信抖动直接触发状态切换。

## 6. 踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `roslaunch` 下模型联网下载 | cwd 是 `ROS_HOME`，相对路径被解析成模型名 | launch 里用「包路径反推仓库根」的绝对路径 |
| 装完 numpy 仍是 1.24 | `pip --target` 遇同名目录静默不覆盖 | numpy 最后单独装 + `--no-upgrade` 先清目录 + 逐包 import 验证 |
| `pip \| tail` 失败仍报成功 | 管道取到的是 `tail` 的退出码 | 先写文件再 `tail`，返回 pip 真实退出码 |
| torch 被拉成 CUDA 版 | ultralytics 依赖会覆盖 | 全部 `--no-deps` 分步装 |
| `cv2` 版本错配 | `opencv-python` 遮蔽系统 cv2 | 装完删除 `lib/m4/cv2*` |

## 7. 已知限制与后续方向

- **类别不适配**：COCO 无 drone 类，仿真目标只能近似成 `kite`。若后续要用于仿真，需要训练专用权重，
  或在仿真场景里换成 COCO 可识别目标。
- **实时性**：CPU 推理 0.5~2 Hz，低于相机帧率。可选方向：降低 `imgsz`、抽帧推理、量化（ONNX/OpenVINO）。
- **数据流联调**（推到 11 月）：仿真器视为一个模块，联调重点在模块间接口一致性，本模块接口已确认可用
  （`image_topic` 参数 + `use_sim_time` 即可接入）。
- `test/M4_现场验证/` 保留为现场复现入口：`demo.sh`（演示 + 网页）、`verify.sh`（16 项自证）。
