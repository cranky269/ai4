# 模型和依赖交接

实测模型来自 https://huggingface.co/sapoepsilon/yolov11s-drone-detector ，单类别0=drone，输入imgsz=640。原best.pt哈希337390e1018eaf815474c02e172a224425095466d4a5cd2dbd11301b0aa01b78。采用已有哈希核验和受限加载流程转换为ONNX，opset17、dynamic=True、simplify=False、nms=False。

复现直接使用随独立验收附件提供的 yolo11s-drone.onnx（37,746,458字节），SHA-256为320ec090ff91a333116d120479f2ad2a9f97a1893e5826e99cf2ad7fd2ca1bd7。Git中不含模型，也没有声称该ONNX已有公开下载链接。组员取得附件后用 sha256sum 校验，再通过启动参数指定绝对路径。启动入口验证哈希且关闭YOLO_AUTOINSTALL，缺依赖即报错。

许可事实分别记录：作者模型页标注Apache-2.0；转换后ONNX元数据保留Ultralytics生成的AGPL-3.0标注；Ultralytics运行库按其自身许可提供。附件保留原始元数据和来源说明，不将整个软件和模型统一声明为Apache-2.0。公开再分发前应由维护者确认各许可对应的分发要求。

隔离基础依赖使用原 install_m4_deps.sh，ultralytics明确固定8.4.173，与本次环境一致。该基础脚本曾用于VM依赖准备，本轮未从空白系统重装torch。新增 install_m4_onnx_deps.sh 在验收副本从空目标目录实际离线安装通过，安装onnx1.16.2、onnxruntime1.19.2、coloredlogs15.0.1、humanfriendly10.0、flatbuffers24.3.25、protobuf4.25.8，复用lib/m4的numpy、sympy与packaging。pip24.3.1以wheel临时运行，不升级系统pip。完整版本和加载路径见联调目录log/runtime-versions.json。

首次回放时Ultralytics自动安装了用户目录onnx1.17.0，导致首帧长时间阻塞。已保存备份、卸载此次新装的用户包，并将onnx纳入隔离目录。最终入口强制关闭自动安装，修正后模型预检与回放通过。没有改系统ROS或全局numpy。全新ROS基础镜像上的完整联网部署尚未重装验证，属于部署证据的边界。
