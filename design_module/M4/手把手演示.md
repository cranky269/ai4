# M4 手把手演示（照着做，一步一步）

> 这份是**操作卡**：每一步只做一件事，敲一条命令，然后对照"该看到什么"。
> 全程约 **3 分钟**。下面的输出都是我**实际跑出来的**，不是编的。
>
> **先记住一句话**：M4 跑在**虚拟机**里，你在**Windows 的浏览器**里看画面。

---

## 第 1 步 · 打开虚拟机窗口

**做什么**：找到你的 VMware 窗口。

- 点 Windows 任务栏的 **VMware Workstation** 图标
- 或者在任务栏找标题写 **「Ubuntu 64 位 - VMware Workstation」** 的那个窗口

**该看到什么**：一个 Ubuntu 桌面（紫色壁纸，左边一列图标）。

> 如果窗口很小，点右上角的**最大化**按钮，放大点好操作。

---

## 第 2 步 · 在虚拟机里打开终端

**做什么**：在虚拟机桌面上，同时按：

```
Ctrl + Alt + T
```

**该看到什么**：弹出一个黑底窗口，最后一行长这样：

```
demo@ubuntu:~$
```

> 这个 `demo@ubuntu:~$` 后面就是你要敲命令的地方。

## 第 3 步 · 敲第一条命令（启动 M4）

**做什么**：在终端里粘贴这一行，按回车：

```bash
cd ~/m4 && bash demo.sh
```

> `~/m4` 是我给你做的短路径（全英文，不用切输入法）。
> 完整路径是 `~/桌面/ai4/test/M4_现场验证/实时演示`。

**该看到什么**：先刷出一串 `[1/6] ~ [6/6]`，然后**停 30 秒左右**（检测模型在 CPU 上要预热，这是正常的，别急）。

## 第 5 步 · 确认"它是活的"（三看）

| 看哪里 | 该看到什么 | 说明 |

## 第 6 步 · 让目标动起来（**这才是真考验**）

前面 `demo.sh` 用的是**一张静态照片**（`camera_node` 的 `image` 源）——
它能证明"链路通"，**但证明不了"能跟踪运动目标"**：框不动、`area_ratio` 恒定。

### 先想清楚一个问题：什么叫"目标在动"？

**跟踪器（以及下游 PID）只看图像像素。** 目标在图像里怎么移动，
它**无法也不必区分**"是目标在动"还是"相机在动" —— 两者在**图像坐标上完全等价**。

而**本任务里相机一定在动**（无人机飞向目标）。所以：

> **「真实照片 + 取景框在动」= 任务里真实发生的情形，这才是对的测试方向。**

> ❌ **我一开始走错过路**：把照片裁一块当"目标贴片"贴在合成背景上滑来滑去。
> 看着"目标在动"，但引入了**现实中不存在的假特征**（硬边矩形、重采样模糊），
> 结果检出断续、状态机掉锁 —— **那才是自欺欺人**。已删除。

### 命令

```bash
cd ~/m4 && bash demo.sh moving     # ★ 推荐：缩放 + 横移（真照片，无合成）
cd ~/m4 && bash demo.sh approach   # 只看"逼近"（目标变大）
cd ~/m4 && bash demo.sh sweep      # 只看"横移"（大小不变）
```

| 模式 | 画面里看到什么 | 主要检验 | 对应 PID 的量 |
|---|---|---|---|
| `approach` | 目标**变大**，中心基本不挪 | 尺度变化 | `area_ratio` → 接近速度 |
| `sweep` | 目标**在画面里横移**，大小不变 | 方向变化 | `bbox` 中心 → `yaw_rate` |
| `moving` | 两者一起（默认） | 两维 | 两者 |

### 该看到什么

1. 横幅写着 `相机源 : video（动态！...）`
2. 页面上**画面真的在动**：目标在变大 / 在横移
3. **`area_ratio` 数字一直变**（静态图时它是恒定值 —— 这是最大区别）
4. **同一个目标的 ID 不变** ← **这才是跟踪成功的证据**
5. 状态通常是 `VISUAL_LOCK`

**`demo.sh moving` 实测**：

```
#1  area=0.137 0.512 0.076   ids=[1,2,3]
#2  area=0.179 0.692 0.129   ids=[1,2,3]
#3  area=0.196 0.652 0.180   ids=[1,2,3]
#4  area=0.116 0.479 0.071   ids=[1,2,3]   ← 视频循环回开头，目标变小
#5  area=0.173 0.634 0.108   ids=[1,2,3]
```

> **判读要点**：目标**动** ＋ **ID 不变** = 跟踪器咬住了它（没跟丢、没换 ID）。

### ★ 但真正的验收证据不是这个视频，而是 **E2E 测试**

视频只是**给人看的**。要被采信，得靠可复现的自动化测试 ——
而这些测试**本来就有**：

| 证据 | 内容 |
|---|---|
| 单测 `test_id_stable_across_moving_frames` | **「跟踪的核心意义：目标连续移动时 ID 保持不变」** |
| 单测 `test_lost_then_recovered_keeps_id` | 丢失一帧后恢复，ID 不变 |
| 单测 `test_two_targets_get_distinct_ids_and_do_not_swap` | 两个目标**不互换** ID |
| 单测 `test_low_score_detection_keeps_id_via_second_stage` | 两阶段关联（低分框保 ID） |
| **E2E 阶段A**（`test/visual_tracker/e2e_test/`） | 假检测源**每帧位移 4/3 像素**，并断言「**框确实在动** + ID 不变 + `area_ratio` 自洽」 |

> ⚠️ **这里刚补了一个漏洞**：原来 E2E 只断言「ID 跨帧稳定」，
> 但**没断言"框确实在动"** —— 跟踪器若偷懒输出一个**固定不变的框**，照样能通过。
> 现在新增了 `~check_move` / `~min_move`（见 `check_tracks.py`），
> 阶段A 会要求「航迹中心跨度 ≥ 100 像素」，**输入在动、输出必须跟着动**才算过。

跑一遍看：

```bash
cd ~/桌面/ai4 && bash test/visual_tracker/e2e_test/run_e2e.sh
```

### ⚠️ 如实说明

**这些都还是合成序列**：没有运动模糊、光照变化、目标遮挡、真实相机抖动。
真正覆盖这些要等 **Gazebo 相机插件 + PX4 闭环**（非 M4 单独可完成）。

想换回静态图：`cd ~/m4 && bash demo.sh`。

## 第 9 步 · 出问题了怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 网页打不开 | 服务没起 / 网址敲错 | 虚拟机里敲 `bash ~/m4/demo.sh status`，看"监听 8090"是不是 1 |
| 网页打开了但**画面不动** | M4 节点没在跑 | `bash ~/m4/demo.sh restart`，等 1 分钟 |
| 画面卡在 `waiting for` | 检测节点还没预热完 | **等 30 秒**，CPU 上加载模型就是慢 |
| 状态一直是**黄色**（没变绿） | 状态机卡住了 | 敲一次 `bash ~/m4/demo.sh restart`（**顺序不能反**：先跟踪器后状态机） |
| 终端报 `没有那个文件或目录` | 不在 `~/m4` 里 | 先 `cd ~/m4` 再执行 |
| 网页显示"服务断开" | 直播服务挂了 | `cd ~/m4 && bash demo.sh` 重来一次 |
| 终端没反应 | 命令还在跑 | **等**（预热 30 秒 + 状态机 6 秒），别急着 Ctrl+C |
| 虚拟机窗口不见了 | 被最小化了 | 任务栏点 VMware 图标 |
| **日志红字 `无法获取图片: .../bus.jpg`** | 素材丢了。旧版把模型/图片放在 `/tmp/m4_infer`，而 **`/tmp` 重启后会被清空**（真踩到：一次重启后图片消失 → 相机节点抛错 → 整条链卡在 `RADAR_GUIDE`，页面上 `frames=0`） | `bash ~/m4/get_assets.sh` 补下；或直接重跑 `demo.sh`（**会自动补下**）。素材现在的正式位置是 `test/M4_现场验证/实时演示/assets/`，**在工程里，重启不丢** |
| **有个画面窗口关不掉**（点 ✕ 没用） | 早期 `live_view.py` 每 30 ms 会重新建窗口（**已修**） | `cd ~/m4 && bash demo.sh stop` —— 现在它连图形窗口一起收 |

> **`demo.sh` 全程不开任何虚拟机窗口** —— 画面全在浏览器里。
> 所以你照这份教程走，**不会遇到"窗口关不掉"**。
> （`m4_live.sh` 是"在虚拟机桌面看"的另一种玩法，那个窗口现在也能用 ✕ 或 ESC 关掉。）

**终极重来**（不管什么毛病都管用）：

```bash
cd ~/m4 && bash demo.sh stop && bash demo.sh
```

## 附 · 为什么是这个流程（一句话版）

```
虚拟机里:  roscore → 直播服务 → camera → detector → tracker → state_machine
                    ↓
Windows 里: 浏览器打开 http://192.168.183.128:8090/
                    ↓
                    看到带绿色检测框的实拍画面 + 状态 + 日志
```

- **顺序为什么不能反**：状态机必须在**跟踪器之后**起，否则约 1 秒就会跳 `SEARCH/RTH` 并卡住（详见 `README.md` 第四节）。`demo.sh` 已经定死正确顺序，你照跑就行。
- **为什么在浏览器看**：M4 的画面是虚拟机内部窗口，宿主机看不到。所以我做了个 HTTP 服务，把画面/状态/日志播出来。
