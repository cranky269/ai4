# M4 视觉检测与跟踪使用说明

本交付以团队 e6a53289f0d58431c3149978787b9c7754fea1d3 为验收基准，保留 a1ffd9e 的最新帧修复和 44c89c8 的 ORT 单线程入口。实际使用 YOLO11s ONNX，CPU、imgsz=640、conf_thres=0.50。跟踪器沿用原版。

## 已安装环境和模型

Ubuntu 20.04、ROS Noetic、Gazebo 11、Python 3.8，以及已构建的 Catkin 自定义消息。首次建立 Catkin 环境请按团队仓库现有构建说明执行，后续 Python 改动无需重复编译。实测视觉依赖为 numpy 1.21.6、torch 2.4.1+cpu、torchvision 0.19.1+cpu、ultralytics 8.4.173、系统 cv2 4.2.0、onnx 1.16.2 和 ONNX Runtime 1.19.2。

在仓库根目录准备隔离依赖。第一条用于尚未安装视觉依赖的新副本，已有环境直接做检查。依赖位于 lib/，不入 Git。

```bash
bash scripts/冲突库下载/install_m4_deps.sh
bash scripts/冲突库下载/install_m4_onnx_deps.sh
bash scripts/冲突库下载/install_m4_onnx_deps.sh --check
```

ONNX 安装入口隔离使用 pip 24.3.1，兼容 Ubuntu 20.04 的旧 pip。支持 `--wheelhouse /path/to/wheels` 离线安装，目录须含这两个 ONNX 包及 coloredlogs、humanfriendly、flatbuffers、protobuf 和 pip 的对应 wheel。已有 lib/m4_onnx 时仅接受检查，安装失败的临时目录保留供排查。脚本运行过程中不使用 sudo，不安装系统 Python 包。

从交付附件取得 `yolo11s-drone.onnx`，放在任意绝对路径。SHA-256 必须为 `320ec090ff91a333116d120479f2ad2a9f97a1893e5826e99cf2ad7fd2ca1bd7`。来源、许可标注及交接方法见本目录 `模块说明文档/模型与依赖.md`。默认 COCO yolov8n 不包含 drone 类，不能作为本次无人机演示模型。

## M0 → M4

在本工程根目录运行。使用 M0 本次启动创建的 connection.bash。启动器仅启动 M4 两个节点，检查重复节点、模型哈希及 ORT 版本，固定 intra/inter 线程为1，日志写到打印的 M4_LOG_DIR。Ctrl+C 停止本入口创建的两个节点。

```bash
bash test/flow/M0-M4/run.sh \
  --connection /本次M0数据目录/connection.bash \
  --model /绝对路径/yolo11s-drone.onnx
```

若复用另一工程已编译的消息，在命令前设置 `M4_ROS_SETUP=/绝对路径/catkin_ws/devel/setup.bash`。旧环境的 ORT 目录可用 `--ort-deps /绝对路径/onnx-deps` 指定。

预检模型和依赖可执行：

```bash
bash test/flow/M0-M4/run.sh --model /绝对路径/yolo11s-drone.onnx --check
```

同一 ROS 环境下用 `rosrun image_view image_view image:=/detector/debug_image` 查看检测图，用 `rostopic echo /visual/tracks` 查看 id、bbox 和 area_ratio。框为原图像素的左上角 x,y 和宽高 w,h，area_ratio 由实际图像尺寸计算。两路数组消息本身没有 Header，调试图保留源图 Header。发生跨帧分析时，使用日志与调试图源时间进行关联。

## 参数和输出语义

发布成功时，无目标产生空 Detections，跟踪器收到空检测后推进失联计数并发布空 VisualTrackArray。慢推理时仅保留最新待处理帧，重复、过期、时钟暂停或回退产生的旧结果不发布。转换或推理失败会记录错误并停止本次输出，以区别正常空目标。因主动跳帧，输出跟随实际推理节拍；这与正式接口文档的“随相机帧率”表述存在节拍差异，已在验收表列为待组长确认的实现取舍。

正式启动入口锁定已验证的模型哈希、0.50 和640。其他原有参数从 config/detector.yaml、visual_tracker.yaml 加载，修改后需重启节点并重新验证。原 detector.launch 支持 model_path 参数，其余 YAML 参数应在对应配置或节点私有参数中设置。运行中 rosparam set 不会自动刷新已经读取的参数。

## 当前效果与限制

真实Gazebo实测已验证相机接入、drone检测、两路消息、无目标空数组、离场清轨和重入建轨。11月11日单线程输出2.575Hz，VM总CPU利用率75.2%；两线程更慢，保留单线程。低置信漏检、异常框和ID重建仍存在，不宣称稳定身份识别或全部性能指标达标。

状态机的0.8置信度和0.02面积比、PID与整机控制验收由对应负责人负责，当前远距场景不保证进入VISUAL_LOCK。M4仅交付接口与感知功能，未修改这些阈值或启动控制链。第一阶段跟踪候选、几何恢复、ReID、雷达融合均未合入。
