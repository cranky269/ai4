## 6. 停止记录、退出和确认没有遗留

分步运行正常顺序：

1. 如需立即停止载机预设，在B调用 `rosservice call /camera_motion_demo/stop '{}'`；它仅取消载机后续位姿命令，保留当前姿态，目标仍运动。若已经自动完成也可调用；不等于停止Gazebo。
2. 在C按Ctrl-C，等rosbag收尾结束；不要关闭终端强杀仍在写入的bag。`rosbag info "$AI4_DATA_DIR/camera.bag"` 应可读，记录数量须非0。
3. 关闭自己另外打开的相机查看器；在A按Ctrl-C，等待本次roslaunch结束。统一入口则在其终端Ctrl-C或调用自身stop，等最终结果。
4. 只读检查 `pgrep -a -x gzserver` 和本轮原ROS/Gazebo端口；存在其他实例时只确认归属，不停止它们。连接被拒绝仅是退出证据之一，还须看自己的PID是否消失。

异常时先看本轮launch.log/runner.log。确认某个具体roslaunch PID与本轮连接端口、启动时间对应后，才由启动者向该PID发SIGINT。不要使用pkill/killall或清空所有ROS/Gazebo。`gazebo_static.py stop`只管理它自己的入口，不能停止这里的shell场景。

## 9. 常见问题：观察、检查、处理

| 现象 | 只读检查 | 处理 |
| --- | --- | --- |
| rosrun/包找不到 | `command -v rosrun`；`rospack find uav_sim`；打印ROS_PACKAGE_PATH | 每个终端按第3节加载ROS和本工作区；核实不是旧源码树 |
| 未构建/自定义消息失败 | `test -f "$AI4_ROOT/catkin_ws/devel/setup.bash"`；`rosmsg show uav_tracking/CentroidArray` | 首次按第2节构建，缺mavros_msgs等依赖则先准备，失败不继续启动 |
| Gazebo或窗口不出现 | `xdpyinfo`；`printf '%s\n' "$DISPLAY" "$XAUTHORITY"`；看launch.log | 真实桌面终端执行，核对插件和模型；一键入口还须满足屏幕尺寸，不承诺无头渲染 |
| 有窗口但相机无图像 | 核对本轮ROS_MASTER_URI；`rostopic info /uav/front_camera/image_raw`；`rostopic echo -n 3 /clock` | clock不推进先看仿真暂停；clock正常再查相机插件和同一master；不以静态画面像素不变判故障 |
| 端口占用/连错实例 | `pgrep -a -x gzserver`；核对A输出与connection；`rosnode list` | 不另起默认roscore；复用自己的实例或由原启动者停止，拒绝重复启动不等于项目坏了 |
| 模型或插件找不到 | `rospack find uav_description`；检查libgazebo_ros_camera.so与本轮launch.log | 准备对应Gazebo11/Noetic资源，确认包路径；不改他人文件或造个人路径软链补洞 |
| 预设服务失败 | `rosservice list`；status响应；目标节点/载机节点日志 | 刚启动先等就绪；非原点载机需已有home返回后再run；连接异常不伪造成功 |
