## 2. 终端 A：构建与启动

每个新终端独立设置 `AI4_ROOT` 为自己的修订版目录。以下构建步骤在仓库根执行：

```bash
cd "$AI4_ROOT"
source /opt/ros/noetic/setup.bash
cd catkin_ws
# 仅全新工作区缺少该文件时初始化，不覆盖已有文件：
if [ ! -e src/CMakeLists.txt ]; then catkin_init_workspace src; fi
catkin_make -DPYTHON_EXECUTABLE=/usr/bin/python3 -j2
source devel/setup.bash
cd "$AI4_ROOT"
rospack find uav_sim
rosmsg show uav_tracking/CentroidArray
test -x catkin_ws/devel/lib/uav_sim/ray_cloud_bridge
```

构建退出0、消息可查看、包路径指向本次目录才继续。请保留错误日志；构建成功不等于节点启动成功。脚本依赖源码树和 `devel/`，不是经验证的 install-space 通用入口。

启动前只读检查 `pgrep -a -x gzserver`，若已有实例先确认归属，不擅自关闭。下表命令从仓库根执行，一次只选一行：

| 用途 | 实际入口 | 正常现象 |
| --- | --- | --- |
| 静态相机 | `bash catkin_ws/src/uav_sim/scripts/start_static_scene.sh` | Gazebo静态Iris及红蓝标志物，发布图像；默认不自动开图像窗口 |
| 已有8字运动学演示 | `bash catkin_ws/src/uav_sim/scripts/start_static_scene.sh gui:=true dynamic_target:=true markers:=false` | 目标运动、自动打开机载相机窗口；是位姿驱动演示，非飞控飞行 |
| 平面传感器及标定板 | `bash catkin_ws/src/uav_sim/scripts/start_static_scene.sh lidar:=true lidar_calibration:=true` | 同一场景内相机与 `/lidar/scan`，中心射线约5米；默认噪声0 |
| 三维传感器及标定靶 | `bash catkin_ws/src/uav_sim/scripts/start_radar_3d.sh calibration:=true` | 同一场景内相机与 `/radar/points`；桥接打印收到181×5射线 |

无桌面时，可在所选 shell 命令后加 `gui:=false camera_view:=false` 仅用于静态入口；三维入口只加 `gui:=false`（其 launch 没有 camera_view 参数）。无窗口不等于相机可无渲染运行，仍须核查消息到达；无头渲染能力待本机验证。三维零噪声可加 `noise_stddev:=0`，配置文件入口为 `config:=/自己的绝对路径/radar_3d.yaml`；默认参数文件 `catkin_ws/src/uav_sim/config/radar_3d.yaml`，默认径向噪声标准差0.02米。

相机、平面扫描可在同一静态入口共存；三维 launch 自带静态场景和相机，内部禁用平面传感器。不要再额外启动静态场景；本说明不提供平面与三维同时运行方案。图像显示、RViz、bag和只读订阅可共享一个场景。静态入口有 flock/gzserver 防重复检查，三维入口没有同等检查；随机独立端口也不能替代实例归属检查。

另一已有静态管理入口是 `/usr/bin/python3 catkin_ws/src/uav_sim/scripts/gazebo_static.py start`，固定GUI、静态、标志物开启、平面关闭，并管理image_view；与上表择一使用。`status|stop` 只管理它记录的实例。迁移后的 `camera_motion_command.py` 是该管理入口的运动演示客户端；同包 `camera_motion_demo.py` 是launch服务/TF节点，不可互换。普通读取不需要调用运动服务。详见 [运动演示](camera_motion_demo.md)、[8字场景](figure_eight_target.md)。

## 4. 传感器接口与数据类型

依据修订提交的 `models/*/model.sdf`、`launch/*.launch`、`config/radar_3d.yaml`、`src/ray_cloud_bridge.cpp`，以及本机 sensor_msgs 消息定义。话题均为绝对名。

| 输入 | 消息类型 / frame_id | 字段、单位及编码 |
| --- | --- | --- |
| `/uav/front_camera/image_raw` | sensor_msgs/Image；uav_camera_optical_frame | header；width=640、height=480像素；encoding=rgb8（SDF R8G8B8）；step为每行字节数；data长度应为step×height；is_bigendian随消息读取，禁止按BGR直接解释RGB |
| `/uav/front_camera/camera_info` | sensor_msgs/CameraInfo；同相机光学frame（运行时再确认） | width/height；K[9]内参、R[9]旋转、P[12]投影、D畸变；plumb_bob，配置畸变全0；像素焦距与主点单位为像素。历史实测K为[554.254691,0,320.5;0,554.254691,240.5;0,0,1] |
| `/lidar/scan` | sensor_msgs/LaserScan；lidar_link | angle_min/max/increment弧度；181条，-π/4至π/4；ranges米，range_min/max=0.1/10米；intensities为插件强度值，无物理标定单位保证；scan_time/time_increment单位秒，若输出0则不能当作扫描周期 |
| `/radar/points` | sensor_msgs/PointCloud2；radar_link | 默认width=181、height=5；organized云，行=垂直ring，列=水平column；point_step=24、row_step=4344字节；is_dense=false；data按fields偏移与消息字节序读取 |

三维点字段（每项count=1）：

| 字段 | 类型 | 字节偏移 | 意义 |
| --- | --- | --- | --- |
| x/y/z | FLOAT32 | 0/4/8 | 雷达frame下米 |
| range | FLOAT32 | 12 | 原始径向距离米，保留非有限值 |
| ring/column | UINT16 | 16/18 | 从最小垂直/水平角开始的零基索引 |
| status | UINT8 | 20 | 0无回波/无效；1量程内部；2低于下限（含-inf）；3下限边界；4上限边界 |

21～23字节为填充；不要把点当成连续XYZ三浮点数组。桥接用本机原生字节序写数据并设置is_bigendian，本机x86为小端；消费者仍应读消息标志。默认水平±45°、垂直±10°、5层，共905条物理射线；`x=r cos(v)cos(h), y=r cos(v)sin(h), z=r sin(v)`，角度按索引线性递增。

**坐标与TF：** world→uav_base_link 来自 `/gazebo/get_model_state` 实际位姿；初始机体(0,0,0.12)米，运动演示时会变化。uav_base_link→uav_camera_link=(0.20,0,0.12)米、单位旋转；uav_camera_link→uav_camera_optical_frame 位移0、xyzw=(-0.5,0.5,-0.5,0.5)。机体/相机安装frame为X前Y左Z上，光学frame为Z前X右Y下，不能混用。world→lidar_link=(0,-2,1)米、单位旋转；world→radar_link默认同位姿，可由三维入口x/y/z参数同时改变spawn与TF。两个测距frame为X前Y左Z上，不装在运动机体上。

**时间与频率：** 相机sensor配置15仿真Hz、插件updateRate=0表示不二次节流；平面10仿真Hz；三维5仿真Hz。三维stamp直接复制Gazebo LaserScanStamped.time，非接收墙钟。相机/平面由Gazebo ROS插件发布；历史图像stamp随仿真推进，消息契约为采集时间；当前仓库不含插件实现，相机/平面插件逐行时间戳赋值及平面特殊值分支仍待验证，不把本机插件实现猜成已核对源码。/clock是仿真时钟，暂停时不推进。仿真实际频率=(N-1)/(末stamp-首stamp)，墙钟频率=(N-1)/(末接收单调时间-首接收单调时间)。`rostopic hz`默认受ROS时间影响，可用 `rostopic hz --wall-time /radar/points` 比较墙钟；均受采样窗口、丢包和负载影响。历史修订三维60帧实测约4.995仿真Hz/4.563墙钟Hz，不承诺15Hz墙钟相机率。

**无效值：** 图像没有逐像素“无回波”码；黑色像素不能判为传输故障。拒绝长度、编码或尺寸不合契约的帧。平面扫描只使用有限且在range_min/max内的ranges，丢弃NaN、±inf和越界值；当前插件分别如何表示近端/远端，待现场核实，不自行填10米。三维桥接：有限区间内（含边界）保留XYZ；非有限或越界点XYZ为NaN，range保留原值；+inf/NaN通常status0，-inf及低于下限为2。噪声截断到边界的有限点为3/4，不能当作未截断高斯样本；盲区内物体不保证有回波。三维是几何Ray测距简化模型，不是完整电磁雷达。

参数细节见 [相机](front_camera.md)、[平面](planar_lidar.md)、[三维](radar_3d.md)。若旧专题说明与本文验证时间边界不同，以本文明确列出的修订证据为准。

## 5. 普通只读程序：显示与记录

所有程序须加载同一工作区、连接同一ROS master，解释器可导入rospy和sensor_msgs；图像转换额外需cv_bridge/OpenCV。不要使用未核对的Conda/venv替换系统Python。没有项目自定义消息也能读取这些标准传感器消息；自定义程序如导入uav_tracking，必须先生成其消息。

**图像显示，终端 B：**

```bash
rosrun image_view image_view image:=/uav/front_camera/image_raw __name:=ai4_readonly_image
```

应出现640×480机载画面；8字入口已自动开窗口时直接使用现有窗口。RGB显示转换交给工具，保存时保留原encoding。普通程序可先用上述header/hz检查持续性，不必启动算法节点。

**点云显示，终端 B：**

```bash
rviz
```

Global Options中Fixed Frame设为 `world`；Add→PointCloud2，Topic选择 `/radar/points`，Color Transformer选择FlatColor或AxisColor（没有rgb字段）。应看到有限回波点；无效点不显示。若TF尚未收到可暂设Fixed Frame=`radar_link`区分TF故障与点云缺失。平面使用Add→LaserScan、Topic=`/lidar/scan`、Fixed Frame=`world`或`lidar_link`；不把平面误选为PointCloud2。

可复制到 B 的最小只读点云有效点检查（不写项目文件、不发布消息；示例本次只做语法核验，运行待验证）：

```bash
/usr/bin/python3 - <<'PY'
import math
import rospy
from sensor_msgs.msg import PointCloud2
from sensor_msgs import point_cloud2
rospy.init_node('ai4_cloud_reader', anonymous=True)
def receive(msg):
    valid = 0
    total = 0
    for x, y, z, status in point_cloud2.read_points(
            msg, field_names=('x', 'y', 'z', 'status'), skip_nans=False):
        total += 1
        valid += int(status in (1, 3, 4) and all(math.isfinite(v) for v in (x, y, z)))
    rospy.loginfo('stamp=%.6f frame=%s points=%d finite=%d',
                  msg.header.stamp.to_sec(), msg.header.frame_id, total, valid)
sub = rospy.Subscriber('/radar/points', PointCloud2, receive, queue_size=1)
rospy.spin()
PY
```

连续多帧stamp递增、默认总点数905、标定场景有限点数大于0是基础检查。queue_size=1适合显示，允许丢旧帧，不是无损记录器。无标定靶时finite=0可能是环境没有可见碰撞体；要结合clock、帧持续性、标定场景和launch日志判断。

**数据记录，终端 C（先完成第3节连接）：**
