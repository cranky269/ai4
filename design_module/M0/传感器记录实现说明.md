# M0 传感器记录实现拆分

## 1. 复用与边界

基于 cranky269/ai4 develop 83e0f46915b95f13b806d8a012f59d29313af289。直接复用上游 ai4_radar_3d/model.sdf、静态Iris相机、目标模型、双机轨迹和 ray_cloud_bridge；上游 detector/visual_tracker、其他算法/节点/测试以及 design/skill 完全保留。未新增纯算法库或改变既有业务接口。

## 2. 模块职责与调用

start_static_scene.sh 在显式 radar:=true 且 dynamic_target:=true 时转入 start_mounted_radar.sh。默认路径保持上游。prepare_mounted_radar.py 将既有相机模型和原生Ray装配到每轮生成world，不覆盖仓库模型；mounted_radar.launch 复用 static_uav.launch 的暂停、world参数，启动桥接、源审计、记录器、相机话题别名、观测机预设重复器和联合查看器。

sensor_source_audit.cpp 通过 Gazebo transport 独立记录原始传感器时间戳。ray_cloud_bridge.cpp 仅增加录制就绪门控，原点云字段转换保留。start_sensor_clock.py 等待源审计/记录/接口/cluster/可选查看器就绪后解除暂停。

audited_cluster.py 动态加载本树上游 ClusterNode，子类调用原回调成功后写输入审计；不修改 uav_tracking、code 或原聚类算法。cluster输出由原订阅/算法/发布处理，审计不重新实现算法。重复获取有限点仅用于输入计数；簇数列留空，以原发布消息验证输出数。

record_radar.py 使用有界队列和单写线程保存原bag/每帧NPZ及PNG；写盘积压时暂停物理并记录背压事件。sensor_session.py 仅管理自己的launch进程组，停止时先暂停、等待在途消息，再SIGINT并等写入收尾。两个运动节点仅对暂时性ROS服务错误重试，轨迹与接口不变。

check_radar_run.py/check_sensor_run.py 重开原始数据并与独立源审计核对。find_sensor_run.py 按关闭状态、错误、完整性、文件存在和校验时效查找成功记录。open_sensor_run.sh 建立独立master，sensor_viewer.py 以原时间间隔调度、最近时间配对展示原图/点云。离线master使用墙钟，防止向前/向后跳帧导致RViz时钟重置清空显示。

## 3. 依赖与风险

新增ROS/桌面运行依赖登记于uav_sim/package.xml，算法版本沿用根requirements.txt并补充传递依赖。运行环境只在本工作区新建.venv-sensors，系统numpy保持1.17.4。未将旧build/devel/venv或传感器数据移入Git。

Noetic本机RViz/SIP析构存在历史崩溃；只读查看器停止订阅/更新并刷新输出后，按Qt退出码使用进程退出避开不稳定析构。采集写入器独立正常关闭，不以该退出规避数据错误。install空间及全新机器依赖安装未验收。
