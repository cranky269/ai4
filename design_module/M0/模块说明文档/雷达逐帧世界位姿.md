# M0 世界坐标及逐帧同步

## 坐标定义

`world` 是 Gazebo `base_scene` 世界 SDF 的固定坐标系：原点为 SDF `(0,0,0)`，地面 z=0，x/y 为 SDF 水平轴，z 向上，右手系。场景没有地理定位，不将 x/y 解释为真实东/北。长度米、角度弧度。

`/radar/uav_pose_world` 的参考点为观测机 `static_uav` 的模型原点，与既有 `uav_base_link` 约定一致。当前 base_link 与模型原点重合；若安装链中 base_link 有固定偏移，仍回算到模型原点。机体轴 x 前、y 左、z 上；orientation 为机体相对 world 的单位四元数（ROS x/y/z/w）。不是雷达中心，也不是目标 `target_uav`。

## 同帧数据链与方案 A

1. Gazebo 原生 `LaserScanStamped.time` 是扫描采样时间。`scan.ranges`、扫描角度属于雷达局部系，`scan.world_pose` 是同帧雷达世界位姿。
2. `ray_cloud_bridge.cpp` 校验原生位姿并归一化允许误差内的四元数，每个有效点实际计算：

```
p_sensor = range * [cos(elevation)*cos(azimuth),
                    cos(elevation)*sin(azimuth), sin(elevation)]
p_world = R_world_sensor * p_sensor + t_world_sensor
T_world_body = T_world_sensor * inverse(T_body_sensor)
```

3. `/radar/points` 的实际 XYZ 为 world，header.frame_id 固定为 world；配置其他 frame_id 会拒绝启动。`range` 仍是雷达到回波点的原始测距，不能用 world XYZ 到世界原点的距离替代。组织布局、ring/column/status、无效 XYZ=NaN 及原始 range 保留，不额外加噪声。
4. `/radar/uav_pose_world` 与该帧点云使用完全相同的原生 sec/nsec；没有查询发布时刻的最新位姿、没有 TF 插值，也没有读取目标真值。
5. 雷达 world_pose 已含完整安装链，点云只变换一次。只有回算机体参考点时应用完整安装链的逆，不能再次把安装偏移叠加到点云上。

`prepare_mounted_radar.py` 从实际生成模型解析 model→base_link→ray_3d 的完整平移和三轴旋转，写入 `radar_pose.yaml`。默认是 `(0.30,0,0.12,0,0,0)`。不支持的 SDF relative pose/frame graph、含 joint 的模型及非法固定 pose 明确拒绝；没有支持任意复杂 SDF 图的声明。

原异步 `/camera_motion_demo/actual_pose` 与 world→uav_base_link TF 保留，但不用于本轮扫描转换。TF 静态安装链保留供其他消费者使用，world 点云在 RViz world 固定系中不再次经过安装变换。

## 无效数据与时间回退

原生世界位姿缺失、嵌套字段未初始化、数值非有限、四元数范数误差超过 1e-3、机载父框架不符、扫描布局/时间/角度或范围限制非法时，记录错误并抑制该帧点云和配对位姿。绝不退回局部点云并标成 world。机体回算非有限时也不发布该帧点云。

扫描时间回退时桥接告警，下一帧仍只使用本帧原生位姿，没有跨帧缓存。标准 ROS 消息不包含 epoch；两话题跨连接不保证原子交付或到达顺序。消费者按原始采样时间和各自连续运行 epoch 精确配对，缺失时明确标记，不沿用上一帧。订阅起止边界及跨连接迟到消息不能仅靠时间戳识别运行身份。

## 显示、持久化与历史记录

- 实时及离线查看器的 RViz Fixed Frame 为 world，直接显示 XYZ；不再自行平移/旋转。
- 原记录器现同时记录 `/radar/uav_pose_world`，raw.bag 保留两路原消息；NPZ 保存 frame_id、coordinate_units=m、range_reference=sensor、coordinate_schema=2、simulation_epoch。
- `frames.csv` 追加 epoch，新增 `radar_poses.csv` 保存 epoch、原始 sec/nsec 和完整机体世界位姿。各流按接收顺序检测时间回退，`check_pose_pairs` 用 `(epoch,sec,nsec)` 精确配对，缺失/重复明确报告。不依赖 bag 按时间排序后的顺序推断重置边界。重置也保留原记录器 timestamp discontinuity 错误统计，不能把重置记录说成连续无间断采集。
- 新终端 `sensor_live.sh pose|record|list` 的动态活动实例发现和停止入口保留；显式录制仍保存两话题 bag。其通用 bag 检查器遇到重复采样时间会报错，不把跨 reset 的不明确数据判成通过；跨重置的可靠配对应使用自动记录器保存的 epoch 索引。
- 历史 frame=radar_link 或未知 frame 的记录在 world 查看器中明确拒绝，原文件不重写；没有当时的雷达世界位姿时不能自动迁移。NPZ 与 CSV 的 frame 均检查。图片/点云离线浏览若时间回退会明确拒绝，需先按采集 epoch 分段，避免 nearest 匹配跨重置。历史纯点云数值验收仍按保存的 frame 展示，不重贴标签。
