# 世界坐标统一（本次实施与边界）

以 Gazebo SDF 固定 world 原点为基准，右手系，z 向上；x/y 是场景 SDF 的正 x/正 y，正 yaw 从 +x 向 +y，不能称为地理东/北。长度米，角度弧度。ROS 四元数 xyzw，主动旋转将机体/传感器向量旋至 world；Gazebo 构造顺序 wxyz。机体 x 前 y 左 z 上。

## 数据源行为

XYZ 实际变换后 frame 只能是 world；配置其他 frame_id 启动失败。原 stamp、24 字节布局、range/ring/column/status 保留。非法距离的 XYZ 继续 NaN；非法扫描世界位姿整帧拒绝，不能保留局部云并贴 world。安装偏移仅在回算无人机参考点时取逆；点云不重复应用它。

查看器固定 world。新记录器保存逐帧世界位姿，检查器和离线查看器拒绝 radar_link 数据；历史记录不迁移、不改写。仿真重置须按 epoch 清缓存，不能跨 reset 用重复 stamp 配对。

## 实际代码链检查

mounted_radar.launch → audited_cluster.py → 原 ClusterNode → filter_ground(world z) → DBSCAN → /radar/centroid。无 TF 二次转换。tracker 的位置差、最近邻门限是 world 中欧氏相对距离，速度和 6×6 协方差均在 world 状态空间估计，不需对已经 world 的新量测再旋转。导航首航点保持 world 数值，忽略 yaw 的位置指令不具有姿态控制验收含义。TrackArray 无 header，不能独立识别旧记录参考系；接口结构受保护，当前只可在 world 数据源会话中新建 tracker，不能注入历史局部航迹。

正式传感器入口只启动 cluster；guidance_modules.launch 另启 cluster/tracker/navigator/...，直接叠加会重复启动 cluster。尚未擅改既定模块调用/接口。

## M3-01 核实与阻塞

本机 package.xml 确认为 MAVROS 1.19.0；对应官方 1.19.0 官方源码 setpoint_raw.cpp local_cb 明确对非 BODY 分支 position/velocity/acceleration 做 ENU→NED；yaw 转换、yaw_rate z 取反；反馈 handle_position_target_local_ned 做逆转换。来源：https://github.com/mavlink/mavros/blob/1.19.0/mavros/src/plugins/setpoint_raw.cpp 。因此不能因 frame 枚举 1 就在 navigator 再交换轴；这会造成重复变换。此为指定条目允许的“明确由谁转换”核实，**不是本机实际 MAVLink 报文及飞控闭环验收**。

尚无已确认的 T_world_local、飞控本地原点创建/重置规则；本机 MAVROS 已确认为 1.19.0，仍缺实际报文往返证据。不能假定与 Gazebo 原点重合。若确认水平旋转 R 和平移 t，则 p_local=R^T(p_world-t)、v_local=R^T v_world、a_local=R^T a_world；协方差用 diag(R^T,R^T) C diag(R,R)，机体姿态 q_local_body=q_local_world q_world_body；之后才由 MAVROS 做协议轴转换，反馈按逆链回 world。未确认关系前不启用该公式下发。

受保护《函数接口》6 指定 PID BODY 且不订阅位姿，7 指定 mux 不透明原样转发；《函数调用关系图》固定反馈仅到 navigator。要在最终适配层完成统一需组长明确新的边界归属与姿态/原点输入接口。按项目规则保留实现，报告受阻，未修改受保护设计。
