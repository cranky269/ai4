# M0 数据类型文档

## 范围与单位

描述当前代码已有数据，不新增或更改design/定义。项目文件路径均相对于根目录，ROS名称和frame不属于文件路径。长度为米、角度为弧度、时间为秒。geometry_msgs/Quaternion字段顺序是x,y,z,w；固定安装单位姿态为(0,0,0,1)。world为Gazebo世界，机体x向前、y向左、z向上；radar_link数据不预先转换到world。光学变换以现有TF四元数(-0.5,0.5,-0.5,0.5)为准。

## 位姿与控制消息

| 数据 | 字段与类型 | 语义 |
| --- | --- | --- |
| geometry_msgs/Pose | position:Point(float64 x/y/z)，orientation:Quaternion(float64 x/y/z/w) | 模型原点位置与姿态，不是传感器中心 |
| geometry_msgs/PoseStamped | header:std_msgs/Header；pose:Pose | header含seq:uint32、stamp:time(secs/nsecs)、frame_id:string；实际与期望分不同话题 |
| gazebo_msgs/ModelState | model_name:string；pose:Pose；twist:Twist；reference_frame:string | 当前命令用static_uav/target_uav及world；Twist含linear/angular Vector3，默认零 |
| geometry_msgs/TransformStamped | header；child_frame_id:string；transform平移Vector3/旋转Quaternion | 观测机实际pose驱动world→uav_base_link；安装变换使用静态发布器 |
| rosgraph_msgs/Clock | clock:time | Gazebo仿真时间，暂停时不推进，回退时目标重置相位 |
| uav_tracking/CentroidArray | centroids:geometry_msgs/PointStamped[] | 以catkin_ws/src/uav_tracking/msg/CentroidArray.msg为准，数组外层没有header；每个点自行带header |

TriggerResponse为success:bool、message:string；SetBool请求为data:bool，响应success/message。状态读取成功不代表图像或雷达功能验收通过。

## Demo状态JSON

/camera_motion_demo/state的String.data与status服务的message均为JSON：

| 键 | 类型 | 含义 |
| --- | --- | --- |
| mode | string | idle/demo/home；连续轨迹时mode仍可能为idle |
| phase | string | 如continuous_sim_orbit、initial_hold、return_home、complete |
| elapsed_wall_s | number | 历史字段名；非连续为墙钟经过秒，continuous=true时实际为当前仿真秒 |
| actual_xyz_yaw | 四元素数组 | 实际x/y/z/yaw，来自GetModelState |
| stamp | number | 实际响应头时间转浮点秒 |
| desired_xyz_yaw | 四元素数组或null | 本轮命令；idle时可为null |
| method | string | 标记SetModelState和kinematic/static语义，不表示飞控闭环 |

## 雷达配置dict/YAML

来源catkin_ws/src/uav_sim/config/radar_3d.yaml，生成副本radar.yaml。水平/垂直采样数为整数，其余为数值；当前值如下。

| 字段 | 当前值 | 单位/含义 |
| --- | --- | --- |
| horizontal_samples / vertical_samples | 181 / 25 | 水平列数/垂直环数，总4525 |
| horizontal_min_angle / horizontal_max_angle | -0.7853981633974483 / 0.7853981633974483 | 弧度，±45° |
| vertical_min_angle / vertical_max_angle | -0.17453292519943295 / 0.17453292519943295 | 弧度，±10° |
| range_min / range_max | 0.1 / 10.0 | 米 |
| range_resolution | 0.001 | 米，距离分辨率，不是角度采样插值倍率 |
| update_rate | 5.0 | 仿真Hz，配置目标而非本轮实测 |
| noise_mean / noise_stddev | 0.0 / 0.02 | 米，原生Ray径向高斯噪声 |

## PointCloud2二进制布局

源码catkin_ws/src/uav_sim/src/ray_cloud_bridge.cpp。width为水平列数181，height为垂直环数25，point_step=24字节，row_step=24×width；按ring优先、column其次组织，index=ring×width+column。is_dense=false，is_bigendian按实际主机字节序设置，不应假定所有机器小端。header.stamp保留原生LaserScanStamped时间，frame_id固定world。

| 字段 | PointField类型 | 字节偏移 | 语义 |
| --- | --- | --- | --- |
| x | FLOAT32(7) | 0 | [R_world_sensor p_sensor+t_world_sensor].x，米 |
| y | FLOAT32(7) | 4 | [R_world_sensor p_sensor+t_world_sensor].y，米 |
| z | FLOAT32(7) | 8 | [R_world_sensor p_sensor+t_world_sensor].z，米 |
| range | FLOAT32(7) | 12 | 原始径向距离，可能包含无效/非有限值 |
| ring | UINT16(4) | 16 | 垂直环索引，从0开始 |
| column | UINT16(4) | 18 | 水平列索引，从0开始 |
| status | UINT8(2) | 20 | 下表分类 |
| 填充 | 不声明为PointField | 21–23 | 对齐字节，初始化为0 |

全部字段count=1。有效点要求range有限且位于闭区间[range_min,range_max]，否则XYZ为NaN。status=0表示无效/无回波类别（含高于最大值或非有限值）；1为区间内部；2为小于最小值；3为最小边界；4为最大边界。边界判定直接比较浮点值，不是容差判定。桥接仅转坐标，不再加噪声。

## 相机消息（只核对实现，未验收画面）

sensor_msgs/Image保留header、height/width:uint32、encoding:string、is_bigendian:uint8、step:uint32及data:uint8[]。记录器支持rgb8/bgr8/mono8，按step裁剪行数据，bgr8转RGB后写PNG；其他编码报错。CameraInfo保留header、尺寸、畸变模型及D/K/R/P、binning与ROI等标准字段，转发不重新标定。原始模型图像设置640×480、15仿真Hz；统一入口默认desktop档只在本次世界中改为320×240、10仿真Hz；没有本轮实测帧率和图像质量结论。

## 运行目录与持久化数据

共同路径前缀为data/radar/<时间_UUID>/。尖括号是实际运行目录的说明，不是可直接执行的字面参数。

| 文件 | 主要内容 | 模式限制 |
| --- | --- | --- |
| mounted.world | 本次SDF世界，含观测模型及安装外壳 | 两模式均生成；仅场景无sensor节点 |
| radar.yaml | 上表配置副本 | 两模式均生成，不说明传感器运行 |
| run.json | created_utc:string、status:string、root:string、config:dict、markers:bool、scene_only:bool、note:string | prepare初值prepared_only；root为程序实际绝对定位元数据，不是文档推荐硬编码路径 |
| connection.bash | 本次ROS_MASTER_URI/GAZEBO_MASTER_URI及本地网络变量 | 两模式均生成，端口每次分配 |
| launcher.pid | 启动进程PID文本 | 仅场景分支写入 |
| raw.bag | 原始消息、TF、位姿与时钟等 | 完整传感器记录器创建 |
| frames/%08d.npz | 每帧组织点云数组及元数据 | 完整模式 |
| frames.csv | frame,seq,stamp_sec,stamp_nsec,frame_id,valid_points,file | 完整模式逐帧索引 |
| camera_frames.csv | frame,source_seq,stamp_sec,stamp_nsec,frame_id,encoding,width,height,file | 完整模式图像索引 |
| interfaces/node__detector/images/%08d.png | 源相机图像导出 | 仅暂存不证明detector接收 |
| source_sensor_stamps.csv及其.poses.csv | 原生源审计时间/位姿 | 审计节点启动才有 |
| statistics.json | 记录统计和关闭状态 | 完整模式退出生成，见下文 |

NPZ内x/y/z/range为(height,width)的float32，ring/column为uint16，status为uint8，valid为bool数组且仅按有限XYZ判断；stamp_sec/stamp_nsec为消息头整数时间，frame_id为保存的字符串标量。消费者应按字段名读取，不凭文件序号推断时间。

statistics.json主要字段包括start_utc/end_utc、radar_frames、valid_points、camera_png_frames、queue_drops、sequence_gaps、timestamp_gaps、write_errors、topic_messages、errors、config、mount、first_sim_time/last_sim_time、wall_duration_s、measured_wall_hz/measured_sim_hz、status及loss_scope。零雷达帧或任一丢失/写入错误使status=failed，否则closed；这不能证明Gazebo内部从未漏生成扫描。会话还可将run.json状态改为closed_pending_verification或failed，仍不能等同于离线验收通过。仅场景不走此退出逻辑，缺失statistics.json属于模式预期。

## 验证边界

以上格式来自源码和配置静态核对。相机/雷达消息质量、逐帧存储完整性、原生安装误差与完整下游接收不属于本轮验证。上一轮环境计算成功与用户确认Gazebo正常分别记录，不推导为数据链路验收成功。

## 雷达逐帧位姿补充

新增 `/radar/uav_pose_world` 使用标准 `geometry_msgs/PoseStamped`：`header.stamp` 与该帧点云一致，`header.frame_id=world`，`pose.position` 为观测机模型原点的世界位置（米），`pose.orientation` 为 x/y/z/w 单位四元数。完整参考点、固定安装变换及时间回退配对规则见同目录 `雷达逐帧世界位姿.md`。PointCloud2 布局不变，XYZ 现为 world；range 仍是雷达测距。
