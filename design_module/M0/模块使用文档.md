# M0 使用

命令均在 **ai4 项目根目录**的 Bash 终端执行。当前代码已改为 world，构建和离线测试通过；本轮正式仿真因执行环境禁止本地 socket、无法访问显示而未完成验收，不能将以下步骤视为本轮已验证的实时效果。首次环境预检查另发现 SciPy 缺失。

## 启动

```bash
source /opt/ros/noetic/setup.bash
catkin_make -C catkin_ws -DPYTHON_EXECUTABLE=/usr/bin/python3 -j2
bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh
```

需要已具备项目依赖和可访问的图形桌面；不要重复启动。默认显示双机、相机及雷达云图，不录制。雷达 XYZ 与云图固定系均为 Gazebo `world`。

## 新终端查看世界位置

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh pose
```

自动定位当前活动实例并加载其连接环境。输出 `/radar/uav_pose_world`：position 是观测无人机模型原点在 world 中的位置（米），orientation 是机体相对 world 的四元数；时间戳与对应雷达扫描相同。不是目标机位置或雷达中心。

查看活动实例：

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh list
```

无实例时先启动；多个实例时按入口打印的完整选择命令执行，不自动猜测实例。

## 录制与停止

仅录制点云和逐帧无人机位姿，在新终端执行：

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh record
```

bag 保存到 `data/radar`，入口打印完整文件路径。先在录制终端按 **Ctrl+C** 并等待保存，再在启动终端按 **Ctrl+C** 停止本次仿真；位置查看终端同样用 Ctrl+C。不要全局杀 ROS/Gazebo。

需要逐帧 NPZ、图片和采样 epoch 索引时，先正常停止当前实例，再启动自动记录模式：

```bash
bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh record:=true
```

产物保存到入口打印的 `data/radar/<本次运行目录>`：`raw.bag`、`frames/*.npz`、`frames.csv`、`radar_poses.csv` 和图片。点云与机体位姿用 `(epoch,stamp_sec,stamp_nsec)` 精确配对；历史局部数据不能直接按 world 解释。跨仿真重置的通用 bag 若时间身份不明确，不能按最近时刻配对。

## 回读自动记录

正常停止后，将刚才打印的运行目录粘贴给提示：

```bash
read -r -p '本次运行目录：' M0_RUN_DIR
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
source lib/venv/env.bash
/usr/bin/python3 catkin_ws/src/uav_sim/scripts/check_sensor_run.py "$M0_RUN_DIR"
bash catkin_ws/src/uav_sim/scripts/open_sensor_run.sh "$M0_RUN_DIR"
```

world 查看器拒绝历史 radar_link/未知 frame；跨时间回退的图片/点云浏览需先按 epoch 分段。数值配对可单独检查：

```bash
PYTHONPATH="catkin_ws/src/uav_sim/scripts${PYTHONPATH:+:$PYTHONPATH}" /usr/bin/python3 -c 'import sys,json; from check_radar_run import check_pose_pairs; print(json.dumps(check_pose_pairs(sys.argv[1]),indent=2))' "$M0_RUN_DIR"
```

## 测试

本轮可运行的离线测试：

```bash
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
/usr/bin/python3 test/uav_sim/radar_pose/test_active_run.py
/usr/bin/python3 test/uav_sim/radar_pose/test_world_recording.py
M0_AUDIT_BUILD=$(mktemp -d)
cmake -S test/uav_sim/radar_pose -B "$M0_AUDIT_BUILD"
cmake --build "$M0_AUDIT_BUILD" -j2
"$M0_AUDIT_BUILD/world_cloud_check"
```

离线结果不是仿真验收。恢复本地网络及显示权限、准备齐依赖后，运行真实 Gazebo 回归：

```bash
M0_CHECK_RUN="data/radar/world_validation_$(date +%Y%m%d_%H%M%S)"
/usr/bin/python3 test/uav_sim/radar_pose/run_gazebo_check.py "$M0_CHECK_RUN" "$M0_AUDIT_BUILD/libmodel_pose_audit.so"
/usr/bin/python3 test/uav_sim/radar_pose/compare_model_pose.py "$M0_CHECK_RUN"
/usr/bin/python3 test/uav_sim/sensor_recording/run_e2e.py
/usr/bin/python3 test/uav_sim/sensor_recording/run_replay.py
```

还需从上面的正式入口验证双机画面、world 云图连续刷新、真实固定物体位置及新录制图形回读，保留画面和逐采样数值。失败日志位于启动终端打印的运行目录；详细坐标定义、转换和本轮验证边界见 `模块说明文档/雷达逐帧世界位姿.md`。
